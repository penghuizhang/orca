## 1. 目标

把 Gitee 看板从 `TaskPage.tsx`（14077 行）抽成独立组件，消除单文件超长风险，并产出可复用的 presentational 行构件（L2 文档里的「复用共享 Row 构件 / 预留复用点」）。

## 2. 关键约束（决定实现形态）

- **渲染层 `.tsx` 的 `max-lines = 400`**（`skipBlankLines`+`skipComments`，注释/空行不计数，见 `.oxlintrc.json` 145–149 行）。整块看板搬进一个文件约 478 代码行，会超 400。
- **AGENTS.md 禁止**：任何 `max-lines` disable 注释、以及在 `mobile/.oxlintrc.json` 加 per-file bump。L2 的本意就是「解 max-lines」，不能靠加禁用/bump 绕过。
- **结论**：把行渲染再拆成独立 `GiteeItemRow`，两文件均 < 400。

## 3. 改动清单

### 3.1 新建 `src/renderer/src/components/GiteeTasksBoard.tsx`
- 自包含：原 `TaskPage.tsx` 的 Gitee 状态块（3709–3723）、拉取 effect（5055–5121）、过滤 memo（5125–5144）、看板 JSX 工具栏+表头+列表（11021–11250、11374–11383）。
- effect 去掉 `if (taskSource !== 'gitee') return` 守卫与 `taskSource` 依赖——组件仅在 `taskSource === 'gitee'` 时挂载，守卫冗余。
- 行渲染不再内联，改为 `{filteredGiteeItems.map(item => <GiteeItemRow ... />)}`。

### 3.2 新建 `src/renderer/src/components/GiteeItemRow.tsx`
- 纯 presentational 行构件，参数化 `item` / `onOpen` / `formatRelativeTime`。
- 复用 GitHub 任务的行 markup/间距（六列网格 `70px_minmax(0,3fr)_minmax(90px,1fr)_90px_110px_40px`、状态 token、`GiteeItemDialog` 同款图标），不绑 GitHub 数据流（copy 架构边界保持）。

### 3.3 改 `src/renderer/src/components/TaskPage.tsx`
- 删除 Gitee 状态块、effect、memo、整段 gitee JSX 分支。
- gitee 分支替换为 `<GiteeTasksBoard formatRelativeTime={formatRelativeTime} />`。
- 导入：`GiteeItemDialog` → `GiteeTasksBoard`；清理仅 gitee 使用的导入 `GiteeAccountItem`（类型）、`FolderGit2`、`Checkbox`。

### 3.4 一处有意偏离「纯搬运」的设计决定
`formatRelativeTime` 是 `TaskPage.tsx:643` 的本地工具函数，被 5 处共用（不能移走，否则破坏其他调用点）。未把它复制进新文件（避免重复），而是作为 **prop** 传入 `GiteeTasksBoard` → 透传给 `GiteeItemRow`。这是最小侵入、零重复的做法。
