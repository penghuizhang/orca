## Gitee 看板适配新 TaskPage 结构

### 背景
上游将 TaskPage 从单文件重构为模块化结构（`task-page/` 目录），每个 provider 有自己的子目录。Gitee 看板组件（`GiteeTasksBoard.tsx` + `GiteeItemRow.tsx` + `GiteeItemDialog.tsx`）仍然存在于 `components/` 根目录，但未被新 TaskPage 导入。

### 改动方案（极简，3 个文件）

**1. 新建 `src/renderer/src/components/task-page/gitee/Content.tsx`**
- 封装现有 `GiteeTasksBoard`，传入 `formatRelativeTime`
- 从 model 中取 `formatRelativeTime`

**2. 修改 `src/renderer/src/components/task-page/Content.tsx`**
- 在 `taskSource` switch 中增加 `'gitee'` 分支，渲染 `GiteeContent`

**3. 移动组件到新目录（可选但推荐）**
- `GiteeTasksBoard.tsx` → `task-page/gitee/GiteeTasksBoard.tsx`
- `GiteeItemRow.tsx` → `task-page/gitee/GiteeItemRow.tsx`  
- `GiteeItemDialog.tsx` → `task-page/gitee/GiteeItemDialog.tsx`
- 更新 import 路径

### 不需要改动的部分
- TaskPage.tsx（组合层）：gitee 是自包含看板，不需要额外 hook
- ListChrome.tsx / SourceBar.tsx：gitee 不需要 provider filter 或 mode controls
- Surface.tsx：gitee 不需要全局 dialog
- IPC / preload / main 进程：已有完整的 gitee API

- typecheck:web 通过
