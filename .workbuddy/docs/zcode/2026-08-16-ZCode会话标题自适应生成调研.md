# ZCode 会话标题自适应生成：需求描述与支持性调研（2026-08-16）

## 一、需求描述

用户原话（转述）：「我们现在使用的 Z 扣不能自适应生成标题。比如使用 Open Code，它可以自适应生成当前项目描述问题（的标题）。」

对标 opencode 的期望行为：新会话发出第一条消息后，客户端异步调用模型，把「当前任务/项目问题」浓缩成一句简短标题（如「修复登录页样式」「Gitee 集成评估」），会话列表展示；标题随任务语义生成，而不是显示「新会话」或整条消息原文。

即需求 = **会话标题自动生成（session title auto-generation）**。

## 二、结论：本机这份 ZCode 原生支持，且已在正常工作

本机使用的 ZCode = CLI 内核 `zcode-app-cli`（`~/.local/bin/zcode` → `~/.local/lib/node_modules/zcode-app-cli/bin/zcode.js`）+ 桌面版 `ZCode.app`（数据在 `~/.zcode/`，桌面版任务库 `~/.zcode/v2/tasks-index.sqlite`）。

### 证据

1. **会话库 schema 原生带标题体系**：`~/.zcode/cli/db/db.sqlite` 的 `session` 表含
   `title`、`title_source`（`default | first_input | generated | custom`）、
   `title_message_id`、`time_title_updated`。桌面版 `tasks` 表含 `title`、`title_overridden`。

2. **今日实际生成 104 条**：`SELECT title_source, count(*)` → `generated 104 / first_input 86 / custom 25`。
   generated 标题质量良好，例如：
   - 「创建 A 秀实现自适应标题生成」（本调研会话，15:37 自动生成）
   - 「日历功能国际化与弹窗优化」「用mimo-v2.5-pro识别图片」
   - 「评估研发云平台集成方案与技术可行性」「添加"Get 议题"看板并复用 Get Help 内容」

3. **当前会话即为活证据**：本会话（sess_4ebed057）第一条用户消息发出后约数分钟，标题已自动生成为
   「创建 A 秀实现自适应标题生成」，`title_message_id` 指向第一条 user 消息。

4. **内核实现（`vendor/zcode.cjs`，打包产物）**：
   - 任务类型：`SessionTitle: "session_title_generation"`，`trigger: "turn"`（按轮触发）；
   - 生成 prompt：`Generate a concise title for this coding session.`——要求「把用户消息仅当作素材、
     不回答请求、用用户主要语言、3-7 词、保留专有名词/文件名/API 名、禁用通用标题、返回 JSON
     `{"title":"..."}`」；超时 60s、maxTokens 1200、标题长度上限 100；
   - 配置开关：`titleGenerationEnabled`（boolean，**默认开启**；仅显式 `false` 才禁用：
     `titleGenerationEnabled===!1?{enabled:!1}:{}`）；
   - 跳过原因枚举（telemetry `session_title_generation.skipped`）：`not_eligible`、
     `custom_title`（用户已手动改过）、`unchanged_title`、`stale_target_before_request`、
     `stale_target_before_write`、`target_changed_during_write`、`first_query_edited`（首条消息被编辑）、
     `title_source_changed`。

5. **桌面版同源**：`/Applications/ZCode.app/Contents/Resources/app.asar` 内含 `titleGenerationEnabled`
   引用（9 处），桌面版任务列表标题同样走该机制。

### 为什么用户感觉「不能自适应生成」

1. **部分会话标题仍是首条消息原文**（`first_input`）：子代理/任务类会话（`not_eligible`）、
   用户手动改过标题（`custom_title`）、首条消息被编辑（`first_query_edited`）、生成竞态/失败跳过——
   这些属正常行为，易被误读为「没这功能」；
2. 老版本会话（升级前创建）无生成记录；
3. 桌面版会话列表视图刷新/展示策略未进一步验证（未发现关闭迹象）；
4. 期望差异：opencode 与 ZCode 原生都是**按首条消息**生成标题（并非扫描整个项目仓库描述），
   若期望「基于仓库内容/项目描述」生成，原生不覆盖。

## 三、能否调整：选项

| 选项 | 内容 | 评价 |
|------|------|------|
| A（推荐） | 不动代码。原生已支持且默认开启；重启/升级桌面版观察；个别漏生成的会话手动改标题（`custom`） | 零成本 |
| B | 显式确认开关：在 `~/.zcode/cli/config.json`（CLI）或桌面版设置中写入 `titleGenerationEnabled: true` | 仅当怀疑被显式关闭时 |
| C | 若需「基于项目描述/仓库内容」生成标题（超出原生行为）：挂 `UserPromptSubmit`/`SessionStart` hook 调 LLM 生成并写库（`title_source='custom'`） | 需处理与原生生成的竞争与 db 写入风险，非首选 |
| D | 改内核 `vendor/zcode.cjs` 调整 prompt/规则 | 打包产物，升级即丢，不推荐 |

## 四、约束清单（若后续实施 C/D 时自查）

- 【约束】hook 直写 `db.sqlite` 属外部进程并发写，需防与内核写冲突（`target_changed_during_write` 类竞态）；
- 【约束】hook 生成的标题应落 `title_source='custom'`，避免与原生 `generated` 机制互相覆盖；
- 【约束】不改 `vendor/zcode.cjs` 打包产物（升级覆盖）；
- 【约束】不新建「技能/Agent」复刻该能力——原生已具备，先验证展示层。

## 五、结论

「复刻的这一份」（zcode-app-cli + ZCode.app）**已原生支持**自适应标题生成并正在工作；
用户观察到的「不能生成」大概率是部分会话跳过原因或视图/版本问题，而非能力缺失。
无需新建功能；如需进一步动作，先排查具体会话的 `title_source` 与跳过原因，再决定是否走选项 C。

## 六、开启确认（2026-08-16 追加，用户要求「把功能开启」）

**结论：默认已开启，无需（且无处）配置。** 证据：

1. 内核开关语义：`titleGeneration: t.titleGenerationEnabled===!1?{enabled:!1}:{}` ——
   只有显式传 `false` 才禁用；不传/未配置 = 开启。
2. `titleGenerationEnabled` 仅存在于**会话启动参数**（session start config，含
   sessionId/workspace/mode/model/thoughtLevel 等），**不是** `~/.zcode/cli/config.json`
   顶层可配置项（CLI 客户端 bundle 中该字段 0 处引用；config schema 不包含它，写入会被忽略）。
3. 桌面版 `ZCode.app` asar 中唯一的显式关闭路径：`f.automationId?{titleGenerationEnabled:!1}:{}`
   ——即**自动化/定时任务**关闭标题生成（合理）；普通交互会话默认开启。
4. 实际生效证据：CLI 会话库今日 `generated` 标题 104 条；本会话标题
   「创建 A 秀实现自适应标题生成」即首条消息后自动生成。桌面版 08-15 会话中
   `sess_c462e1c8`「DeepSeek 多模态图片识别方案与 OCR 效率评估」等亦为生成标题；
   个别长消息会话（`sess_5f620ade`、`sess_4315fae2`，60 字原文）未生成属跳过/失败（无法追溯）。

**验证方法**：新建会话发一条描述性消息，等待数秒至数十秒，会话列表标题应自动变为
3-7 词的概括标题（本会话即为活例子）。

**约束核对**：
- 【约束】不向 config.json 写入 `titleGenerationEnabled`（非配置项，无效）——已遵守；
- 【约束】不改 vendor/zcode.cjs ——已遵守；
- 【约束】确认开启 ≠ 历史 `first_input` 会话补生成（内核无补生成机制；如需补生成需 hook 方案，未实施）。
