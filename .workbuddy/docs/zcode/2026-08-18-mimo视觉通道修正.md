# 2026-08-18 Mimo 视觉通道修正

## 背景

主模型 deepseek-v4-flash 无视觉。此前视觉委托链路长期不工作：read-image skill 委托目标 `opencode/mimo-v2.5-free` 在网关不存在，`builtInModelOverrides` 指向智谱 `glm-4.6v` 报余额不足（即"视觉子代理余额不足"提示的来源），唯一可用通道被记录为智谱 glm-4.1v-thinking-flash 直连 API。

2026-08-18 实测 opencode 网关（https://opencode.ai/zen/go/v1，provider `opencode-go`）全部 mimo 模型，发现 **`mimo-v2.5`（不带后缀，恰好在 cli/config.json 的 opencode-go provider 里已配置）图片识别成功**（测试图含 ORCA-818 / HELLO 12345 文字，逐行准确读出）。mimo-v2.5-pro 仍 404 拒图、mimo-v2-omni / mimo-v2-pro 上游 Unsupported model。

## 变更内容（3 项，用户已拍板用 opencode-go/mimo-v2.5 做图片识别）

1. **read-image skill**（`~/.agents/skills/read-image/SKILL.md`）：委托目标 `opencode/mimo-v2.5-free` → `opencode-go/mimo-v2.5`，同步更新 description 与「备选（手动切模型）」段落；补充 mimo 家族可用性事实。
2. **子代理模型覆盖**（`~/.zcode/v2/agents-state.json` 的 `builtInModelOverrides`）：`general-purpose` / `Explore` 从 `bigmodel/glm-4.6v` → `opencode-go/mimo-v2.5`，根治"视觉子代理余额不足"。注意：`cli/config.json` 的 `subagents.builtInModelOverrides` 不生效（记忆已确认），刻意不改。
3. **auto-memory 修正**（`zcode-multimodal-vision.md` + `MEMORY.md` 索引行）：把「唯一可用通道=智谱直连」改为「网关侧视觉通道=opencode-go/mimo-v2.5（推荐、已配置生效）；智谱直连降为备选」。
