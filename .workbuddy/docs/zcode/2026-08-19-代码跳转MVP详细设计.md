# 代码 Command 跳转 MVP 详细设计

> 日期：2026-08-19
> 状态：详细设计 / 待评审后实施
> 前置评估：`docs/2026-08-19-代码跳转能力评估与方案.md`
> 目标：实现最小可用的 Command 点击跳转（同文件精准 + 跨文件可用），不引入常驻语言服务

## 1. 目标与非目标

### 1.1 目标（MVP 内做）

- 单文件内：光标处符号（函数/类/接口/type/变量/常量）Command+点击 / F12 / 右键 Go to Definition 可跳到本文件定义处
- 跨文件：上述手势可跳到同 worktree 内其他文件的定义处，新 tab 打开并定位行列
- 交互：悬停出现可跳转下划线，支持 Peek 预览（Monaco 原生），找不到时轻提示不报错
- 语言：首批 `typescript / javascript / python / go`（Monaco 已注册，着色已可用）；其他语言走文本兜底
- 运行环境：native / WSL / SSH 均可用，查询按宿主隔离

### 1.2 非目标（MVP 不做）

- 常驻 LSP（tsserver/pyright/gopls）、重命名/引用查找/重构
- 精准的依赖与别名解析（paths alias、动态 import、宏）
- Diff 视图双 model 跳转（作为可选增强，二期再做）
- 依赖 node_modules / vendor 内的第三方库定义跳转

## 2. 现状与约束回顾

- `src/renderer/src/lib/monaco-setup.ts` 为只读预览关掉三类 TS 校验，仅保留 tokenization
- 无任何 `DefinitionProvider`，grep 为 0
- 打开文件：`src/renderer/src/store/slices/editor/actions/open-file-action.ts` → `openFile` + `openWorkspaceEditorItem`，定位靠 `pendingEditorReveal { filePath, line, column, matchLength }`，挂载时 `useMonacoEditorMount` 通过 `queueReveal` 消费（见 `EditorContent.tsx` / `MonacoEditor.tsx`）
- 全文搜索：`src/renderer/src/components/right-sidebar/useFileSearchRunner.ts` → `searchRuntimeFiles`（ripgrep/grep，支持 caseSensitive/wholeWord/useRegex，`SEARCH_MAX_RESULTS=2000`，防抖 300ms，带 searchId 去重）
- 跨平台：`navigator.userAgent.includes('Mac')` 选 metaKey / ctrlKey，UI 用 `⌘/Ctrl`

**设计约束**
- 【约束】不硬编码 `e.metaKey`，平台分流
- 【约束】不为跳转重新开启全量 TS 语义校验噪音
- 【约束】只读导航，不写文件
- 【约束】查询按宿主/connectionId 隔离，不假定本地
- 【约束】Monaco provider 需可 dispose，避免语言 id 重复注册泄漏

## 3. 总体方案

> `Monaco DefinitionProvider（自定义，纯文本+启发式） + ripgrep 跨文件搜 + openFile/pendingEditorReveal 打开`

```
MonacoEditor (mount)
  └─ useMonacoEditorMount
       ├─ registerDefinitionProvider(typescript, javascript, python, go, …)  ← 新增
       └─ definitionProvider.provideDefinition(position, token)
            ├─ 1) 抽词 getWordAtPosition → word
            ├─ 2) 同文件启发式扫描：definitionPattern.test(word) → Range[]   ← 纯函数，可单测
            └─ 3) 跨文件：searchRuntimeFiles({ query: word, wholeWord:true }) → ranked matches → Location[]
                    ↑ 复用现有 runtime 搜索，带 connectionId/worktreePath
                           ↓
                    openDefinitionTarget({ filePath, line, column })
                      ├─ 同文件：editor.revealRangeInCenter + setPosition
                      └─ 跨文件：openFile + pendingEditorReveal(两帧 rAF，同 search-match-open.ts)
```

为什么不用 TS Worker：Worker 无法解析项目 import，语义不可信；自定义文本 provider 足够支撑 MVP，且零校验噪音。

## 4. 详细设计

### 4.1 模块划分

```
src/renderer/src/lib/code-navigation/
  ├─ code-navigation.ts                 // 纯函数：抽词、定义正则、单文件扫描、结果排序
  ├─ code-navigation.test.ts            // 单测
  ├─ monaco-definition-provider.ts      // 包装 monaco.languages.registerDefinitionProvider
  ├─ definition-opener.ts               // 同/跨文件打开与定位（openFile + reveal）
  └─ index.ts                           // 导出
```

### 4.2 纯函数层 `code-navigation.ts`

- `extractDefinitionWord(model, position): string | null` — 透传 `model.getWordAtPosition`
- `DEFINITION_PATTERNS: RegExp[]` — 按语言的定义行启发式：
  - TS/JS: `/(?:function|class|interface|type|enum|const|let|var)\s+<word>\b/` , `\<word>\s*\(`, `\<word>\s*[:=]`
  - Python: `/(?:def|class)\s+<word>\b/`
  - Go: `/(?:func|type)\s+(?:\(.*\)\s*)?<word>\b/`
  - 通用兜底：`/\b<word>\b/`
- `findSameFileDefinitionRanges(content, word, language): Range[]` — 按行扫描，返回首个定义行附近的 Range（用于同文件直接 reveal）
- `rankSearchMatches(word, matches: SearchMatch[], currentFilePath): Ranked[]` — 优先定义行（命中 `DEFINITION_PATTERNS` 的文件/行）、同目录邻近文件次之、其余按 ripgrep 顺序；过滤当前文件已由同文件路径覆盖的重复
- 工具：`escapeRegExp`, `isWholeWordMatch`

> 全部纯函数，无 IO，可单测覆盖边界（空词、大小写、wholeWord、跨语言）

### 4.3 Provider 层 `monaco-definition-provider.ts`

- `registerCodeDefinitionProvider(monaco, deps): IDisposable`
  - 对 `['typescript','javascript','python','go','java','rust','cpp','csharp','kotlin','swift','php','ruby']` 批量 `monaco.languages.registerDefinitionProvider`
  - `provideDefinition(model, position, token)`：
    1. 抽词，空则 return null
    2. 同文件：`findSameFileDefinitionRanges(model.getValue(), word, language)` 若命中 → 返回 `[ { uri: model.uri, range: ... } ]`（Monaco 会在同文件内直接跳转，无需 openFile）
    3. 跨文件：若同文件未命中且 `worktreeId` 存在 → 调 `searchRuntimeFiles`（`wholeWord:true`, `maxResults: 20`，带 `connectionId`），对结果做 `rankSearchMatches`，取 top 1-3 转 `Location { uri: monaco.Uri.file(filePath), range }`
    4. `token.isCancellationRequested` 时提前退出
  - 异常：搜索失败返回 null，上层 toast 由 opener 负责

> 注意：`model.uri` 在 Orca 中为 `file://` 或 `inmemory`，解析 `filePath` 需从 `model.uri.path` 或挂载时传入的 `filePath` 回填；跨文件返回的 uri 需用绝对路径构造。

### 4.4 打开层 `definition-opener.ts`

- `openDefinitionTarget(params): void`
  - 输入：`{ filePath, line, column, matchLength, worktreeId, worktreePath, language, openFile, setPendingEditorReveal }`
  - 同文件：`editor.revealRangeInCenter(new Range(line, column, line, column+matchLength))` + `editor.setPosition`
  - 跨文件：复用 `search-match-open.ts` 的两帧 rAF 模式
    ```ts
    openFile({ filePath, relativePath, worktreeId, language: detectLanguage(filePath), mode:'edit', runtimeEnvironmentId }, { suppressActiveRuntimeFallback })
    cancelRevealFrame(rafA); cancelRevealFrame(rafB); setPendingEditorReveal(null)
    rafA = requestAnimationFrame(() => rafB = requestAnimationFrame(() => setPendingEditorReveal({ filePath, line, column, matchLength })))
    ```
  - 找不到：`toast.info('No definition found for "word"')`

### 4.5 挂载集成

- `src/renderer/src/components/editor/use-monaco-editor-mount.ts` 注入：
  - 新增 `useMonacoDefinitionProvider`（或直接在 `useMonacoEditorMount` 内调用 `registerCodeDefinitionProvider`），依赖 `worktreeId`、`filePath`、`connectionId`
  - `onDidDispose` 时 `disposable.dispose()`
- `src/renderer/src/components/editor/MonacoEditor.tsx` 透传 `worktreeId`（已有）+ 新增 `worktreePath` 若需要
- `DiffViewer.tsx` / `DiffSectionItem.tsx` 本期不接，留 TODO 注释

### 4.6 快捷键与菜单

- 无需额外注册：Monaco 的 `F12 / Ctrl+F12 / Cmd+F12`、`Cmd/Ctrl+Click`、右键 `Go to Definition / Peek` 均由 provider 存在自动启用
- 悬停下划线由 Monaco 原生提供

### 4.7 运行时序

1. `MonacoEnvironment.getWorker` 已就绪（现成）
2. `useMonacoEditorMount` 回调中先完成 `syncContentOnMount`，再注册 provider
3. 用户悬停时 Monaco 调 `provideDefinition`（可取消）
4. 点击触发 `editor.action.revealDefinition` → 若跨文件，provider 返回的 Location 会触发我们的 `openDefinitionTarget`（通过 `editor.onDidChangeModel` 或直接在 provider 侧调用 openFile；MVP 选择 provider 仅返回 Location，Monaco 默认行为已会在同文件内跳转，跨文件则需拦截：Monaco 对 `file://` uri 会尝试打开新 model，故需在 provider 返回前确保 uri 可被 `openFile` 消费；备选是让 provider 返回空而自行调用 opener——详细实现时二选一，单测覆盖）

## 5. 数据与接口

- 复用 `searchRuntimeFiles`（`src/renderer/src/runtime/runtime-file-client.ts`）签名：
  ```ts
  searchRuntimeFiles({ settings, worktreeId, worktreePath, connectionId }, { query, rootPath, caseSensitive, wholeWord, useRegex, includePattern, excludePattern, maxResults })
  ```
- 新增本地类型 `DefinitionLocation { filePath: string; line: number; column: number; matchLength: number }`

## 6. 交互与空态

- 命中：同文件平滑居中定位并选中符号；跨文件新 tab 打开并定位
- 未命中：`toast.info('No definition found for "xxx"')`，不弹错误
- 超时/取消：静默忽略
- 大文件：单文件扫描为 O(n) 行扫描，n=万行仍 <5ms；跨文件搜索限 20 结果，避免全量

## 9. 风险与回退

- 误跳：启发式正则可能把使用处当定义 → 通过 ranking 优先定义关键字行缓解
- 搜索噪音：同名符号多 → 限 top 3，提供 Peek 让用户自选
- 性能：ripgrep 限 20 结果 + wholeWord，减少遍历
- 回退：provider dispose 即可关闭功能，无持久状态
