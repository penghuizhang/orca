## 2. 现状分析（结合记忆库）

### 2.1 下拉菜单：pi 已是一等 agent 类型，缺的是「探测得到」

- `src/shared/tui-agent.ts` 已含 `'pi' // Pi (pi.dev)`；`tui-agent-config.ts`、`agent-catalog.tsx`（含 PiIcon）、`agent-kind.ts`、`tui-agent-selection.ts` 全部已注册 —— **上游已内置，无需代码改动**
- 下拉菜单显示条件 = `detectCmd` 在 Orca 应用环境 PATH 中探测到 + 未被「智能体设置」禁用
- **根因（本次诊断）**：Orca GUI 环境 PATH 里有 `~/bin`（zcode/opencode/hermes 均在 `/Users/zhangpenghui/bin/` 有入口所以出现在菜单），但 **`~/.local/bin` 不在**；`pi` 只装在 `~/.local/bin/pi` → 探测不到 → 菜单不显示
- 旁证：claude/codex/gemini（装在 /usr/local/bin、/opt/homebrew/bin）同样没出现在菜单

### 2.2 用量统计：zcode 模式是现成模板，pi 数据源不同

- zcode 独立统计已实施（docs/2026-09-03-zcode独立使用统计设计方案.md）：`src/main/zcode-usage/` 模块 + `ZCodeUsagePane` + StatsPane 下拉 tab，数据源是 SQLite `model_usage` 表
- **pi 数据源**：`~/.pi/agent/sessions/<项目slug>/*.jsonl`（会话 JSONL 流水）：
  - 首行 `{"type":"session","id","cwd","timestamp"}`（带 cwd，可做项目归属）
  - assistant 消息行含 `provider/model/usage{input,output,cacheRead,cacheWrite,reasoning,totalTokens,cost{total}}/timestamp` —— 数据完整，含已计费成本
- 数据量：当前 6 个文件共 1.5MB，增长缓慢 → **全量重扫**可接受（zcode 550MB 才需要增量）

## 3. 方案设计

### 3.1 A 部分：下拉菜单 Pi 按钮（无代码改动）

**方案：环境符号链接**（选型理由：pi 支持代码已完备，缺的只是探测；新建符号链接与用户为 zcode/opencode 建 ~/bin wrapper 的既有做法一致，且不碰代码、零上游冲突）

```bash
ln -s ~/.local/bin/pi ~/bin/pi   # 已执行
```

- 生效条件：重启 Orca（探测在启动时进行）
- **待确认①**：是否需要像 ZCode 一样配全局键盘快捷键（⌥⌘T 那样）？不配则仅出现在菜单/搜索列表

### 3.2 B 部分：Pi 用量统计（镜像 zcode 模式）

#### 数据流（与 zcode 完全同构）

```
~/.pi/agent/sessions/**/*.jsonl
  → src/main/pi-usage/scanner.ts（JSONL → events → sessions/daily 聚合）
  → PiUsageStore（UsageProviderStoreLifecycle，缓存 userData/orca-pi-usage.json）
  → IPC piUsage:getScanState/setEnabled/refresh/getSnapshot/...
  → preload piUsageApi
  → renderer PiUsageSlice → PiUsagePane + PiUsageDetails → StatsPane 新 tab "Pi"
```

#### 新增文件（9 个）

#### pi 特有的设计决策

| 决策点                 | 选择                                                                                      | 理由                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 扫描策略               | **每次全量重扫**（对比 mtime/size 仅作缓存元数据）                                        | 数据量小（1.5MB）；zcode 的跨文件增量合并复杂度高、易错 |
| 项目归属               | session 头 `cwd` 与 worktree 路径最长前缀匹配 → `displayName`；无匹配回退 `basename(cwd)` | pi 记录了 cwd，能比 zcode（无归属）多出真实的项目分布   |
| 模型/provider 集合     | session 内存 `string[]`（非 Set）                                                         | JSON 持久化无损，避免 zcode 的 Set 反序列化补丁         |
| 成本                   | 累加 assistant 行 `usage.cost.total`（无 model 时记 0）                                   | pi 已记录计费成本，可直接展示「Recorded cost」          |
| UsageOverviewPane 总览 | **不加**（仅独立 tab）                                                                    | 控制范围；overview 卡片加 pi 可后续迭代                 |

## 5. 影响分析

- **范围**：纯新增模块 + 既有注册点各一行级改动；不触碰上游热路径（persistence/tab/agent 启动），上游同步冲突面≈0
- **性能**：全量扫描 1.5MB 级 JSONL（毫秒级）；缓存 5 分钟 STALE_MS 复用既有生命周期；不随 zcode 550MB 场景恶化
- **兼容**：`PI_SESSIONS_DIR` 缺失/为空目录时扫描返回空，面板显示空态；Web 客户端 `window.api.piUsage` 为 undefined，slice 已有 undefined 短路
- **平台**：Windows 路径走 `USERPROFILE`；JSONL 读取用 Node 流，无平台分支
