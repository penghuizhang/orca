# 2026-08-16 zcode 多模态（图片识别）配置诊断与影响说明

## 背景

主模型为 DeepSeek V4 系列（纯文本，无视觉）。全局 read-image skill 规定贴图时委托 vision 子代理，但用户反馈"切换模型后图片仍不能处理"，怀疑多模态配置失效。

## 诊断结论（全部实测验证）

### 1. 根因链

| 层 | 现状 | 实测证据 |
|---|---|---|
| 主模型商 | `opencode-go`（opencode.ai/zen/go 网关），仅 deepseek-v4-flash/pro | 带图请求被网关协议层拒绝：`unknown variant image_url, expected text` |
| skill 委托目标 | read-image 声称用 `opencode/mimo-v2.5-free` | 该模型名在网关实测返回 `Model mimo-v2.5-free is not supported`（无效模型名） |
| 用户自配模型 | 桌面版 v2 的 opencode 商下有 mimo-v2.5-free | `modalities.input=["text"]`（无视觉标注），且网关不认 |
| 全部可选模型 | deepseek×2、glm-5.2、gpt-5.6-luna、mimo-v2.5-free | 逐一实测：均无视觉（glm-5.2 网关收图但模型自述无多模态能力） |

**结论**：不是切换模型动作的问题，而是所有可选项都不支持图片输入；read-image skill 中的 mimo 委托指引从未生效。

### 2. 唯一可用通道

智谱 API key（`v2/config.json` 的 `builtin:bigmodel-coding-plan` 内，a54f0e1a…）可调用**免费视觉模型 `glm-4.1v-thinking-flash`**，实测识别图片正确（输出"红色"）。付费视觉模型 glm-4.6v/4.5v/5v-turbo 返回余额不足（code 1113）。

## 已做配置变更（可逆，均为 zcode 全局配置，非工程代码）

1. `~/.zcode/cli/config.json`
   - 新增 `bigmodel` 商：openai-compatible，baseURL=`https://open.bigmodel.cn/api/paas/v4`，apiKey=智谱 key；models 含 `glm-4.1v-thinking-flash`、`glm-4.6v`
   - `subagents.builtInModelOverrides`：general-purpose / Explore → `bigmodel/glm-4.1v-thinking-flash`
2. `~/.zcode/v2/agents-state.json`（新建）
   - 同款 `builtInModelOverrides`（zcode 源码确认这是桌面版子代理模型覆盖的读取路径）

## 验证状态与待办

- CLI `--prompt` 单次模式实测覆盖未生效（子代理仍走 deepseek）——该模式与桌面版配置加载路径不同
- **待用户验证**：重启 zcode 桌面版 → 新会话贴图 → 子代理应使用 glm-4.1v-thinking-flash 成功读图
- 失败备选：① 智谱充值开通 glm-4.6v；② 主模型换原生视觉模型（Claude/Gemini 系列）

## 影响面

- 不涉及 orca 工程代码、不涉及上游同步
- 仅修改 zcode 全局配置（~/.zcode/），可随时回滚
- 若桌面版验证通过，后续贴图流程无需用户手动切换模型
