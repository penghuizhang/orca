# 代码 Command 跳转能力评估与方案

> 日期：2026-08-19
> 状态：评估 / 待评审（未动代码）
> 关联需求：阅读代码时 Command 点击方法名跳转到定义，支持跨文件逻辑追踪

## 1. 背景与现状

- 用户场景：日常大量阅读代码，当前只能看当前文件，无法 Command 点击进入方法/类型定义，逻辑分析效率低。
- 现状实现：
  - 代码渲染走 `src/renderer/src/lib/monaco-setup.ts` + `src/renderer/src/components/editor/MonacoEditor.tsx` / `DiffViewer.tsx`，基于 `monaco-editor@0.55` + `@monaco-editor/react`。
  - `monaco-setup.ts` 为只读预览场景把 TS 语义/语法校验全关了（`noSemanticValidation/noSyntaxValidation/noSuggestionDiagnostics`），只保留 tokenization 着色；未注册任何 `DefinitionProvider` / `ReferenceProvider`。
  - `grep` 全仓无 `provideDefinition` / `goToDefinition`，即当前无任何跳转能力。
  - 文件通过 worktree 文件系统加载，编辑器为只读/半只读态，未接语言服务（LSP）或项目级符号索引。
- 已有可复用资产：仓库已接入 CodeGraph（tree-sitter 全量符号图，`codegraph_*` MCP），可秒级回答「定义在哪、谁调用谁、改动影响面」，无需另起语言服务即可做结构化导航。

## 2. 能否实现

**能做。** 技术上是 Monaco 标准能力（`languages.registerDefinitionProvider`）+ 符号索引 + 编辑器面板打开文件三件套。不涉及后端重构或协议大改，风险可控。

## 3. 涉及面评估

| 维度 | 说明 |
|------|------|
| 核心改动 | `monaco-setup.ts` 注册 provider；`MonacoEditor.tsx` / `DiffViewer.tsx`（及 `DiffSectionItem.tsx`）处理 Cmd/Ctrl+Click 与 Peek；新增符号解析服务（优先复用 CodeGraph，其次 TS Worker） |
| 打开文件 | 复用现有 `EditorPanel` / worktree 打开链路（`editor-panel-*`、`useEditorPanelFileContentLoader`），需支持「跳转到文件+行列并推入 tab」 |
| 跨平台 | 快捷键按 `navigator.userAgent.includes('Mac')` 区分 `metaKey` vs `ctrlKey`；UI 提示 `⌘/Ctrl`；符合 AGENTS.md 跨平台约束 |
| 远程/WSL/SSH | 文件解析在宿主侧（native/WSL/SSH）执行，需按宿主维度作用域，与现有 Git capability 隔离思路一致；仅做只读导航，不触及 `Remote Wire Compatibility` 的新 opcode |
| 语言覆盖 | TS/JS 可由 Monaco TS Worker 先做到单文件内跳；跨文件及 Python/Go 等需 CodeGraph 或 LSP |
| 工作量 | MVP（单文件+CodeGraph 跨文件 TS）约 3-5 个文件；全量 LSP（多语言+依赖解析）则需常驻服务，工作量与维护成本翻倍 |

**结论：涉及面中等。** 不算全局重构，但需横跨「编辑器挂载、符号索引、文件打开」三层，属中等范围的横切功能。

## 4. 方案对比

### 方案 A：MVP（推荐先做）

- 原理：Monaco TS Worker 负责单文件内精准跳转；CodeGraph 负责跨文件符号跳转（TS/JS/Python/Go 等 tree-sitter 已覆盖的语言）。
- 优点：零常驻进程、复用已有索引、实现快、维护轻；满足 80% 阅读场景。
- 缺点：依赖解析（别名、动态 import、宏）不如完整 LSP 精准。
- 改动点：`monaco-setup.ts` 注册 `DefinitionProvider`；新增 `src/renderer/src/lib/code-navigation/`（provider + CodeGraph 查询 + 结果转 `Location`）；`MonacoEditor.tsx` 注入 provider 并在 `onMount` 绑定；Diff 视图可选支持。

### 方案 B：完整 LSP

- 原理：每个 workspace 起对应语言的 `tsserver/pyright/gopls` 等，通过 `monaco-languageclient` 或自建 IPC 桥接。
- 优点：最精准，支持重命名、引用查找等。
- 缺点：需管理多进程生命周期、版本兼容、WSL/SSH 透传、资源占用大；实现与维护成本高。
- 适用：作为二期，在 A 验证价值后再按需接入单语言（如 TS）。

### 方案 C：纯文本兜底

- 原理：当前文件内正则/词法查找同名符号，仅高亮/搜索。
- 优点：最轻。
- 缺点：误跳率高，跨文件不可用，体验差。仅作降级。

## 5. 推荐路径

1. 先做方案 A 的 MVP：单文件 TS 跳转 + CodeGraph 跨文件，支持 `Cmd/Ctrl+Click` 与 `F12 / Cmd+F12`，提供 Peek 预览与跳转二选一。
2. 验证有效后再评估是否引入 TS 的 LSP 精化；其他语言继续由 CodeGraph 覆盖。

## 6. 交互与约束

- 触发：`Cmd (Mac) / Ctrl (Win/Linux) + Click`，悬停下划线提示可跳；支持右键「Go to Definition」与 `F12`。
- 行为：同文件内直接滚动定位；跨文件在当前 EditorPanel 新 tab 打开并定位行列；找不到定义时 toast 提示，不报错。
- 约束清单：
  - 【约束】快捷键必须按平台区分 `metaKey`/`ctrlKey`，不得硬编码 `e.metaKey`。
  - 【约束】只读预览场景不引入写操作或诊断噪音，不重新开启全量 TS 校验。
  - 【约束】符号查询按宿主隔离（native/WSL/SSH），不假定本地执行。
  - 【约束】CodeGraph 索引滞后时以文件读取为准，banner 提示的 pending 文件走实时读取。
  - 【约束】Diff 视图中 provider 需同时处理 original/modified 两个 model。
