# 代码跳转：方法定位错乱修复（影响说明）

> 日期：2026-08-20
> 状态：已实施，待评审 / 待合入 custom
> 关联：`docs/2026-08-19-代码跳转MVP详细设计.md`

## 1. 问题

Command/Ctrl+Click 或 F12 跳 `chatService.sseChat(chatRequest)` 时，没跳到 `sseChat` 方法定义，而是打开了一个「其他文件」（错误页面），且即使打开正确文件也未定位到方法行。

## 2. 根因

MVP 的 TS/JS 定义识别正则只命中**关键字声明**：

```
(?:function|class|interface|type|enum|const|let|var)\s+<word>\b
```

而 `sseChat(chatRequest): Promise<...> {`、`async sseChat(...)`、`const sseChat = () =>`、`sseChat: (req) =>` 这类**方法 / 箭头函数声明一个都没命中** → `isDefinition` 恒为 `false`。

`rankSearchMatches` 在 `isDefinition` 全为 `false` 时退化为「按文件名 `localeCompare` 排序」，于是取**字母序最靠前**、且恰好含 `sseChat` 的文件（往往是一个调用处文件），打开即成「其他页面」。

> 注：实际导航链路是 `code-navigation-trigger.ts` + `code-navigation-bindings.ts`；`definition-opener.ts` / `monaco-definition-provider.ts` 是设计遗留的未接入口死代码，本次不动。

## 3. 修复

`src/renderer/src/lib/code-navigation/code-navigation.ts` 把布尔 `definitionPatternForLanguage` 改为**打分函数 `declarationScoreForLine`**：

- 关键字声明（`function/class/...` / `const x =`）→ 3 分（原行为保留）
- 方法 / 箭头声明：`(?<![\w.$])(?:modifiers\s+)*<word>\s*\??\s*(?:\(|[:=]\s*\()` 命中
  - **负向后顾 `(?<![\w.$])`** 排除成员访问调用 `obj.sseChat(` / `this.sseChat(`
  - 前置上下文若是调用语境（`=`、`return`、`await`、`new`、`(`、`foo(`、`?`、`,`、`;` 等）→ 判为调用，0 分
  - 否则 → 2 分（真声明）
- `rankSearchMatches` 改为**按 score 降序**，同名号时同文件去重、再按 文件/行 稳定排序；调用处一律 0 分，声明文件必然排在最前

覆盖：TS/JS 的 `function`、类方法、接口方法、async 方法、对象/类属性箭头（`=>`、`:`）、`const x = () =>`；Python `def/class`、Go `func/type`、Java/Kotlin 等关键字声明保持原样。

## 4. 影响面

- 改：`code-navigation.ts`（纯函数层，无 IO）
- 不改：`code-navigation-trigger.ts` / `code-navigation-bindings.ts` / `definition-opener.ts` / `monaco-definition-provider.ts`（后者仍为死代码）
- 行为变化：跨文件跳转从「字母序第一文件」改为「定义行优先」，精准落点方法行并 `pendingEditorReveal` 居中定位
