# ZCode 独立使用统计设计方案

## 1. 背景与需求

### 1.1 现状
- 当前 Orca 的使用统计面板中，zcode 的使用量被合并到 OpenCode 统计中
- OpenCodeUsagePane 中有说明："ZCode usage is included in OpenCode statistics as ZCode uses OpenCode APIs"
- 用户希望 zcode 能作为独立统计项，与 opencode 同等地位显示

### 1.2 目标
- 为 zcode 创建独立的使用统计面板
- 在统计面板的下拉菜单中添加 "ZCode" 选项
- 显示 zcode 的 token 使用量、会话数、模型分布等统计信息

## 2. 技术分析

### 2.1 ZCode 数据库结构
ZCode 使用独立的 SQLite 数据库 `~/.zcode/cli/db/db.sqlite`，包含以下相关表：

#### model_usage 表（核心使用统计）
```sql
CREATE TABLE model_usage (
  id text primary key,
  session_id text not null,
  turn_id text,
  provider_id text not null,
  model_id text not null,
  input_tokens integer not null default 0,
  output_tokens integer not null default 0,
  reasoning_tokens integer not null default 0,
  cache_creation_input_tokens integer not null default 0,
  cache_read_input_tokens integer not null default 0,
  started_at integer not null,
  completed_at integer,
  duration_ms integer,
  status text not null check(status in ('running', 'completed', 'error', 'cancelled')),
  -- ... 其他字段
);
```

#### turn_usage 表（轮次使用统计）
```sql
CREATE TABLE turn_usage (
  session_id text not null,
  turn_id text not null,
  input_tokens integer not null default 0,
  output_tokens integer not null default 0,
  reasoning_tokens integer not null default 0,
  started_at integer not null,
  completed_at integer,
  duration_ms integer,
  -- ... 其他字段
);
```

### 2.2 数据量
- 当前 zcode 数据库中有 25,694 条使用记录
- 使用的 provider 包括：opencode-go、bigmodel、company-custom 等

### 2.3 Orca 使用统计架构
Orca 的使用统计系统基于 `UsageProvider` 接口：
- `id`: 提供者标识（UsageProviderId）
- `label`: 显示名称
- `schemaVersion`: 缓存版本号
- `scan()`: 扫描函数，返回使用数据

当前支持的提供者：claude、codex、opencode、plugin:*

## 3. 设计方案

### 3.1 扩展 UsageProviderId 类型
在 `src/main/usage/usage-provider-contract.ts` 中添加 'zcode'：
```typescript
export type UsageProviderId = 'claude' | 'codex' | 'opencode' | 'zcode' | `plugin:${string}`
```

### 3.2 创建 ZCode 使用统计模块
新建目录 `src/main/zcode-usage/`，包含以下文件：

#### 3.2.1 types.ts
定义 zcode 使用统计的类型：
- `ZCodeUsageScanState`: 扫描状态
- `ZCodeUsageSummary`: 使用摘要
- `ZCodeUsageDailyPoint`: 每日使用点
- `ZCodeUsageBreakdownRow`: 分类行
- `ZCodeUsageSessionRow`: 会话行
- `ZCodeUsageSnapshot`: 完整快照

#### 3.2.2 zcode-usage-provider.ts
实现 `UsageProvider` 接口：
```typescript
export const zcodeUsageProvider = {
  id: 'zcode',
  label: 'ZCode',
  schemaVersion: 1,
  scan: scanZCodeUsageDatabases
} satisfies UsageProvider<...>
```

#### 3.2.3 scanner.ts
实现数据库扫描逻辑：
- 读取 `~/.zcode/cli/db/db.sqlite`
- 解析 `model_usage` 表中的使用记录
- 聚合统计信息（token 使用量、会话数、模型分布等）
- 支持按时间范围过滤

#### 3.2.4 zcode-database-discovery.ts
发现 zcode 数据库：
- 默认路径：`~/.zcode/cli/db/db.sqlite`
- 支持环境变量 `ZCODE_DB` 覆盖
- 检查数据库文件是否存在

### 3.3 创建 ZCode 使用统计 UI 组件
新建 `src/renderer/src/components/stats/ZCodeUsagePane.tsx`：

#### 3.3.1 功能
- 显示使用摘要卡片（输入 token、输出 token、缓存 token、推理 token、会话数、成本）
- 按模型分类统计
- 按项目分类统计
- 每日使用趋势图
- 最近会话列表

#### 3.3.2 与 OpenCodeUsagePane 的区别
- 独立的统计面板，不与 OpenCode 混合
- 显示 zcode 特有的 provider 分布（opencode-go、bigmodel 等）
- 支持按 provider 过滤

### 3.4 集成到 StatsPane
修改 `src/renderer/src/components/stats/StatsPane.tsx`：

#### 3.4.1 添加 ZCode 标签
在 `USAGE_ANALYTICS_OPTIONS` 中添加：
```typescript
{
  id: 'zcode',
  get label() {
    return translate('auto.components.stats.StatsPane.zcodeUsageTab', 'ZCode')
  }
}
```

#### 3.4.2 渲染 ZCodeUsagePane
在标签切换逻辑中添加 zcode 分支。

### 3.5 注册 ZCode 使用统计提供者
在主进程中注册 zcode 使用统计提供者，使其参与使用统计扫描。

## 5. 影响分析

### 5.1 代码变更
- 新增文件：约 10 个（类型定义、扫描器、UI 组件等）
- 修改文件：约 3 个（类型定义、StatsPane、使用统计注册）
- 预计代码量：约 1500-2000 行

### 5.2 性能影响
- 数据库扫描：zcode 数据库约 550MB，扫描可能需要 1-2 秒
- 缓存机制：复用 orca 已有的使用统计缓存框架
- 内存占用：增量扫描，不会一次性加载全部数据

### 5.3 兼容性
- 向后兼容：不影响现有 OpenCode 使用统计
- 独立运行：zcode 统计与 OpenCode 统计完全独立
- 可选功能：用户可单独启用/禁用 zcode 统计

## 6. 风险与缓解

### 6.1 数据库锁
- 风险：zcode 运行时可能锁定数据库
- 缓解：使用只读模式打开数据库，实现重试机制

### 6.2 大数据量
- 风险：25,000+ 条记录扫描可能影响性能
- 缓解：增量扫描、只扫描新记录、后台线程处理

### 6.3 路径兼容性
- 风险：Windows 路径差异
- 缓解：使用 orca 已有的路径处理工具函数

## 9. 总结
