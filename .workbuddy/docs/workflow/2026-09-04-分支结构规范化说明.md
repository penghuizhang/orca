# 分支结构规范化说明（2026-09-04）

## 背景

用户要求重新梳理 fork orca 项目的分支结构，确保团队成员对 PR 提交目标分支理解一致，避免二开代码污染纯净分支。

## 变更内容

在以下三个位置同步更新分支结构规范，增加 PR 目标分支的明确约束：

1. `.agents/skills/orca-dev-workflow/SKILL.md` — 分支结构章节
2. ZCode 全局记忆 `orca-dev-workflow.md`
3. ZCode 全局记忆 `MEMORY.md` 索引

## 分支结构

```
upstream/main (官方上游)
    ↓ 同步
main (纯净分支，仅同步上游代码)
    ↓ 同步
custom (二开主干，包含所有二开功能)
    ↑ 合并
feature/xxxx (功能开发分支)
```

## PR 目标分支（核心规则）

| 分支 | PR 目标 | 说明 |
|------|---------|------|
| feature/xxxx | **custom** | 唯一正确的 PR 合并目标 |
| custom | **禁止提 PR** | 二开主干，不往 main/master/orca 提 PR |
| main | **禁止提 PR** | 纯净分支，只接受上游同步的 merge |

**错误做法**：往 main、master、orca 分支提 PR（会导致二开代码污染纯净分支或冲突）。

**正确做法**：feature 分支开发完 → PR 合并到 custom → 定期打包。

## 影响范围

- 无代码变更，仅文档/记忆更新
- 不影响现有功能和打包流程
- 后续所有 feature 分支开发和 PR 提交必须遵循此规范
