## 四、合并与冲突策略

1. **强拉**：`git fetch upstream 'refs/heads/*:refs/remotes/upstream/*' --force` +
   `git fetch upstream 'refs/tags/*:refs/tags/*' --force`，并 `git ls-remote` 核 tip
2. **回退锚点**：`git tag -f backup/pre-sync-20261017 custom && git push origin custom`
3. **冲突预演**：`git merge-tree --write-tree --name-only custom upstream/main`
4. **解冲突**：**禁止 `--ours/--theirs` 一把梭**。按 skill 判「谁改了这个文件」后取舍：
   - 双方各新增并列项 → 并集叠加
   - 顺序不同内容相同 → 取上游排序
   - 新增枚举/注册项 → 并集，多行联合类型
   - 真语义分歧 → **实测优先**（`[官] < [证] < [测]`）
5. **i18n 语言包**：跑 `.workbuddy/skills/upstream-merge-safety/scripts/merge-locales.py` 做三向按键合并，**不手工拼**（防同名同值重复键 / 丢 `}`）
6. **静默重复扫描**：`find-duplicate-ids.mjs --base HEAD^1` —— 两侧各自新增同名 agent id 时 git 零冲突、tsc 只抓一小部分（2026-09-26 实测 11 显式冲突外还藏 7 处）
7. **提交**：`git commit --no-verify`（合并暂存上万文件，lint-staged 会对全部上游文件跑 oxlint/oxfmt）

## 五、合并后门禁（= `pr.yml` 真门禁）

```
pnpm tc                                    # 硬门禁：零冲突 ≠ 集成完成
node .workbuddy/skills/upstream-merge-safety/scripts/find-duplicate-ids.mjs --base HEAD^1
pnpm run verify:localization-catalog
pnpm run verify:localization-runtime-catalog
pnpm run verify:localization-extraction
pnpm run verify:localization-coverage
```

- 冲突文件单独跑 oxlint 5 套配置矩阵 + `oxfmt --check`；**不用** `check:code-quality:changed`（基线 origin/main，合上游后变更集上万文件、几千条存量噪音，不可用）
- `pnpm tc` 前需 `pnpm install`（依赖可能变）
- 门禁**不得用 `cmd | tail` 判成败**（管道把失败显示成 exit 0）

## 六、打包

```bash

cd mobile && pnpm install && cd ..        # mobile 是独立 workspace，根 install 不覆盖
```

- `build-orca-s.mjs` **硬性拒绝非 custom 分支且无跳过开关** ⇒ 同步 PR 必须先合并才能打包
