# Orca 二开工作流程规范

## 概述

本项目是基于 Orca（stablyai/orca）的二次开发（二开）项目。为了确保二开功能不丢失，特制定此工作流程规范。

## 分支结构

```
upstream/main (官方上游)
    ↓ 同步
main (纯净分支，保持与上游同步)
    ↓ 同步
custom (二开主干，包含所有二开功能)
    ↑ 合并
功能分支 (calendar-feature, feature/zcode-agent, etc.)
```

### 分支职责

1. **upstream/main**：官方上游代码
2. **main**：纯净分支，仅同步上游代码，不包含任何二开功能
3. **custom**：二开主干，包含所有二开功能，所有开发基于此分支
4. **功能分支**：具体功能开发，完成后合并到 custom

## 标准工作流程

### 1. 同步上游代码

```bash
# 步骤1：更新 upstream 远程
git fetch upstream

# 步骤2：切换到 main 分支并合并上游代码
git checkout main
git merge upstream/main --no-edit

# 步骤3：推送到 origin
git push origin main

# 步骤4：切换到 custom 分支并合并 main
git checkout custom
git merge main --no-edit

# 步骤5：解决冲突（如有）
# 仔细检查冲突文件，确保二开功能不被覆盖

# 步骤6：推送到 origin
git push origin custom
```

### 2. 开发二开功能

```bash
# 步骤1：基于 custom 创建功能分支
git checkout custom
git checkout -b feature/your-feature-name

# 步骤2：开发功能
# ... 编写代码 ...

# 步骤3：提交代码
git add .
git commit -m "feat(your-feature): 描述"

# 步骤4：推送功能分支
git push origin feature/your-feature-name

# 步骤5：创建 PR 合入 custom
# 在 GitHub/Gitee 上创建 PR，目标分支为 custom
```

### 3. 打包应用

```bash
# 步骤1：确保在 custom 分支
git checkout custom

# 步骤2：拉取最新代码
git pull origin custom

# 步骤3：验证所有二开功能已合并
# 检查是否有未合并的功能分支
git branch --no-merged custom | grep -v upstream | grep -v remotes

# 步骤4：运行打包脚本
node config/scripts/build-orca-s.mjs

# 步骤5：验证打包结果
ls -la dist/*.dmg
```

## 常见问题与解决方案

### 问题1：打包时二开功能丢失

**原因**：功能分支未合并到 custom，或同步上游代码时二开功能被覆盖。

**解决方案**：
1. 打包前检查所有功能分支是否已合并：
   ```bash
   git branch --no-merged custom | grep -v upstream | grep -v remotes
   ```
2. 确保同步流程正确执行，冲突解决时保留二开功能。

### 问题2：同步上游代码时冲突

**原因**：上游代码修改了与二开功能相同的文件。

**解决方案**：
1. 仔细分析冲突，确保二开功能不被覆盖。
2. 参考历史冲突解决记录：`docs/2026-08-18-上游同步v1_4_99影响说明.md`
3. 必要时与团队成员讨论。

### 问题3：版本号不一致

**原因**：本地构建版本包含时间戳和 commit hash。

**解决方案**：
- 当前策略：基础版本号与上游一致，本地构建版本包含后缀。
- 示例：`1.4.178-rc.2.local.1787196977715.6b83fe686edf`
- 如需发布正式版本，手动修改 `package.json` 中的版本号。

## 打包前检查清单

打包前务必确认以下事项：

- [ ] 1. 确认在 custom 分支
- [ ] 2. 确认 custom 分支包含所有二开功能
- [ ] 3. 确认没有未合并的功能分支
- [ ] 4. 运行 typecheck 验证：`pnpm tc`
- [ ] 5. 运行 oxlint 验证：`pnpm lint`
- [ ] 6. 运行打包脚本：`node config/scripts/build-orca-s.mjs`

## 版本号管理

### 版本号格式

- 基础版本号：与上游一致（如 `1.4.178-rc.2`）
- 本地构建版本：`基础版本号.local.时间戳.commit hash`
- 示例：`1.4.178-rc.2.local.1787196977715.6b83fe686edf`

### 版本号更新流程

1. 同步上游代码后，上游版本号会自动更新到 custom 分支
2. 本地构建版本由打包脚本自动生成
3. 如需发布正式版本，手动修改 `package.json` 中的版本号
