# 二开工作流程改进设计（2026-09-02）

## 问题背景

最近两次同步上游代码和打包过程中遇到以下问题：
1. **功能分支遗漏**：打包时发现日历功能缺失，因为 calendar-feature 分支没有合并到 custom
2. **同步流程复杂**：需要手动执行多个步骤，容易出错
3. **版本号管理不明确**：打包版本号与上游大版本一致，但本地构建版本包含时间戳和 commit hash

## 当前工作流程分析

### 现有流程
1. **同步上游代码**：
   - `git checkout main`
   - `git fetch upstream`
   - `git merge upstream/main`
   - `git checkout custom`
   - `git merge main`
   - 解决冲突
   - 推送到 origin

2. **开发二开功能**：
   - 从 custom 切功能分支
   - 开发完成后提 PR 合入 custom
   - 功能分支保留

3. **打包**：
   - 确保在 custom 分支
   - 运行 `node config/scripts/build-orca-s.mjs`
   - 验证打包结果

### 问题点
1. **手动检查多**：需要手动检查所有功能分支是否已合并
2. **容易遗漏**：打包前没有自动验证功能完整性
3. **冲突解决风险**：同步过程中可能引入意外变更

## 改进方案

### 1. 建立功能分支清单

在项目根目录创建 `二开功能清单.md`，记录所有二开功能分支及其状态：

```markdown
# 二开功能清单

## 已合并到 custom 的功能
- [x] 日历功能（calendar-feature）- PR #4
- [x] zcode agent 类型（feature/zcode-agent）- PR #5
- [x] custom.db 业务库（feature/calendar-sqlite）- PR #6
- [x] 日历周概览（calendar-week-summary）- PR #8
- [x] 日历清单历史周月查看优化（calendar-worklist-history）- PR #15
- [x] 浏览器自动化 MCP Server（feat/browser-automation-mcp）- PR #16
- [x] 移除 Gitee 集成（remove-gitee-integration）- PR #18

## 待合并功能
- [ ] 无
```

### 2. 增强打包脚本验证

修改 `build-orca-s.mjs`，在打包前验证：

```javascript
// 在打包前检查功能分支是否已合并
const requiredFeatures = [
  'calendar-feature',
  'feature/zcode-agent', 
  'feature/calendar-sqlite',
  'calendar-week-summary',
  'calendar-worklist-history',
  'feat/browser-automation-mcp',
  'remove-gitee-integration'
];

for (const feature of requiredFeatures) {
  const merged = spawnSync('git', ['branch', '--contains', feature], {
    cwd: repoRoot,
    encoding: 'utf8',
    env
  }).stdout.includes('custom');
  
  if (!merged) {
    console.error(`[orca-s] 功能分支 ${feature} 未合并到 custom！`);
    process.exit(1);
  }
}
```

### 3. 标准化同步流程

创建同步脚本 `sync-upstream.mjs`：

```javascript
#!/usr/bin/env node
// 同步上游代码到 custom 分支

import { spawnSync } from 'node:child_process';

const repoRoot = process.cwd();

function run(cmd, args) {
  const result = spawnSync(cmd, args, { 
    cwd: repoRoot, 
    stdio: 'inherit',
    encoding: 'utf8'
  });
  if (result.status !== 0) {
    console.error(`命令失败: ${cmd} ${args.join(' ')}`);
    process.exit(result.status);
  }
  return result.stdout;
}

// 1. 获取上游最新代码
run('git', ['fetch', 'upstream']);

// 2. 更新 main 分支
run('git', ['checkout', 'main']);
run('git', ['merge', 'upstream/main', '--no-edit']);

// 3. 同步到 custom
run('git', ['checkout', 'custom']);
run('git', ['merge', 'main', '--no-edit']);

// 4. 推送到 origin
run('git', ['push', 'origin', 'main']);
run('git', ['push', 'origin', 'custom']);

console.log('同步完成！');
```

### 4. 版本号管理策略

**当前策略**：基础版本号与上游一致，本地构建版本包含时间戳和 commit hash。

**示例**：`1.4.178-rc.2.local.1787196977715.6b83fe686edf`

**建议**：
- 保持当前策略，这样可以区分官方版本和本地构建版本
- 在打包时显示版本号供用户确认
- 如果需要发布正式版本，可以手动修改 package.json 中的版本号

### 5. 打包后验证

创建验证脚本 `verify-build.mjs`：

```javascript
#!/usr/bin/env node
// 验证打包结果是否包含所有二开功能

import { existsSync, readdirSync } from 'node:fs';
import { resolve } from 'node:path';

const distDir = resolve(process.cwd(), 'dist');

// 检查打包文件是否存在
const files = readdirSync(distDir).filter(f => f.endsWith('.dmg') || f.endsWith('.zip'));
if (files.length === 0) {
  console.error('未找到打包文件！');
  process.exit(1);
}

console.log('打包文件：');
files.forEach(f => console.log(`  ${f}`));

// 检查版本号
const versionMatch = files[0].match(/orca-s-(\d+\.\d+\.\d+)/);
if (versionMatch) {
  console.log(`\n版本号：${versionMatch[1]}`);
}

console.log('\n打包验证完成！');
```
