## 3. 本轮网络前提（头号阻塞，已解）

`git fetch` 拉不动，两个叠加原因：

1. **全局 gitconfig 有 `url.git@github.com:.insteadOf https://github.com/`**：即使用 HTTPS URL，
   git 也会改写回 **SSH**，于是 `http.proxy` 配置完全不生效（症状：速度锁死 25 KB/s、
   `GIT_CURL_VERBOSE` 零输出）。
2. SSH 直连到 GitHub 被限速/挂死（实测 40s 无任何输出）。

**解法（本轮达标写法）**：用**带端口的形式**绕开 insteadOf 前缀匹配：

```bash
git -c http.proxy=http://127.0.0.1:54687 -c credential.helper= \
    fetch https://github.com:443/stablyai/orca.git main:refs/remotes/upstream/main --tags
```

实测：代理 2.4 MB/s vs 直连 26 KB/s（≈90×）；本次 18274 objects / ~22 MiB 顺利拉完。

> 另注：**不要全量拉 `refs/heads/*`**（上游 7982 个分支，全量包 248,953 objects 会卡死）。

## 5. 约束清单（实施中逐条自查）

【约束】必须用带端口 HTTPS + 代理（`https://github.com:443/...`）拉取，否则 SSH 被限速挂死
【约束】不改全局 gitconfig 的 `insteadOf` 规则，只在单次命令上用 `-c` 覆盖
【约束】不碰 `main`；只在 `custom` / `sync/*` 上操作
【约束】冲突禁 `--ours/--theirs` 一把梭，逐条判「谁改了这个文件」
【约束】语言包必须走 `merge-locales.py`；`en-runtime-required.json` 必须用 `--fix` 重新生成
【约束】合并提交必须 `--no-verify`（合并暂存上万文件，lint-staged 会重排上游代码）
【约束】合并**解完立刻提交**（上一轮被并发会话 reset 抹掉过未提交的合并）
【约束】合并后硬门禁 `pnpm tc` 必须零错误 + 本地化四项门禁全过
【约束】静默重复 id 必须跑 AST 差集扫描（`find-duplicate-ids.mjs --base <merge^1>`）
【约束】`custom` 必须含全部二开要素，且 `git merge-base --is-ancestor upstream/main HEAD` 成立（保留上游祖先）
【约束】打包前：`cd mobile && pnpm install`（独立 workspace）+ 清干净未跟踪文件（`verify-features` 只豁免 `?? .codegraph/`）
【约束】Electron 走 `ELECTRON_MIRROR` 环境变量（`.npmrc` 的 `electron_mirror` 对 electron-builder 无效）
【约束】Node 需切 24（工程 `engines.node=24`，当前默认 22.22.3）
【约束】打包只从 `custom` 分支打（`build-orca-s.mjs` 硬性拒绝非 custom 分支）
【约束】打包/安装完成**不自动重启** orca-s（本 agent 会话跑在 orca-s 终端内，重启会杀掉自己）
【约束】`.workbuddy/` 与 `docs/**` 被 gitignore，提交必须 `git add -f`

## 7. 风险与遗留

- **并发会话**：同机存在多个 zcode 会话，上一轮曾因并发 `reset` 抹掉未提交的合并。
  对策：解完立刻提交；提交后即使被 reset 也是 no-op；发现并发立即停止写索引。
- **打包不可并发**（会争抢 `dist/`、`node_modules` 与 Electron 缓存）。
- 装完后**需用户手动 Cmd+Q 重启** orca-s 才会真正生效（本会话无法自杀）。
- 上一轮遗留 `docs/bug-reproductions/.DS_Store` 未跟踪文件，打包前必须清掉。
