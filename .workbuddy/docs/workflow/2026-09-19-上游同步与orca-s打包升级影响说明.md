### 关键发现 1：首次 `git fetch upstream` 静默未更新引用

第一次 `git fetch upstream --tags` 返回 0 且无输出，但远程 `refs/heads/main` 实际已到 `b8f3b1ec00`，本地 `upstream/main` 仍停在 `01d7228b7e`。
改用显式 refspec 强拉后引用才更新：

```bash
git fetch upstream 'refs/heads/*:refs/remotes/upstream/*' --force
```

复用旧引用会导致「以为已是最新、实际两个月没同步」的假同步，**同步前必须核对 `git log -1 upstream/main` 的日期**。

### 关键发现 2：main 分支无法直接合并上游

`git merge-base main upstream/main` 返回空（无共同祖先）——浅克隆的 graft 边界（`.git/shallow` 10 条，2026-08-15 ~ 09-03）切断了 main 的历史。因此**文档中的 `upstream → main → custom` 三步流程在浅克隆下走不通**：main 那一步会因 “refusing to merge unrelated histories” 直接失败。

而 custom 与上游合并基为 `01d7228b7e`（正确的旧上游 tip），可直接合并。故本次**直接 `custom merge upstream/main`**，main 保持不动（它已是 custom 的祖先，且此前 PR #19 已把 custom 合进 main，不再是「纯净分支」）。

## 三、执行步骤

1. 提交工作区遗留知识产物（记忆 / 设计文档），保证合并前工作区干净；
2. 建安全备份 tag：`backup/pre-sync-20260919`（合并失败可一键回退）；

### 6.4 未完成 / 遗留（重要）

1. **main 分支未同步**：浅克隆（`.git/shallow` 10 条 graft）切断了 main 与 upstream/main 的共同祖先，`git merge-base main upstream/main` 为空 ⇒ 直接 merge 会触发 `refusing to merge unrelated histories`。要恢复标准三步流程必须 `git fetch upstream --unshallow`（全量历史下载，带宽成本高），需用户拍板。当前 main 停在 `94db30ceed`（且此前 PR #19 已把 custom 合进 main，已非「纯净分支」）。
2. **应用版本已升级但未生效**：`/Applications/orca-s.app` 已替换为 `1.4.197-local.1789782638720.140117ca1732`，但**正在运行的进程是 9/16 启动的旧版**（daemon 参数里仍是 `...2c4e15b625e8`）。`open` 只会激活旧实例，因为 macOS 不会替换运行中的进程。
   **必须由用户手动重启 orca-s**（Cmd+Q 后重新打开）才会运行新版——本次无法代为重启：本会话自身就跑在 orca-s 的终端里（进程链 `zsh ← zcode-cli ← node ← login ← orca-s Helper(1411) ← orca-s(696)`），退出应用会直接杀掉本会话。
3. **打包版 UI 尚未人工/CDP 验收**：历史踩坑「zustand selector 不稳定导致的渲染错误只在打包版复现」，需重启后确认状态栏正常（无错误边界兜底）。
