### 关键发现 1：首次 `git fetch upstream` 静默未更新引用

第一次 `git fetch upstream --tags` 返回 0 且无输出，但远程 `refs/heads/main` 实际已到 `b8f3b1ec00`，本地 `upstream/main` 仍停在 `01d7228b7e`。
改用显式 refspec 强拉后引用才更新：

```bash
git fetch upstream 'refs/heads/*:refs/remotes/upstream/*' --force
```

复用旧引用会导致「以为已是最新、实际两个月没同步」的假同步，**同步前必须核对 `git log -1 upstream/main` 的日期**。

### 关键发现 2：main 分支无法直接合并上游

`git merge-base main upstream/main` 返回空（无共同祖先）——浅克隆的 graft 边界（`.git/shallow` 10 条，2026-08-15 ~ 09-03）切断了 main 的历史。因此**文档中的 `upstream → main → custom` 三步流程在浅克隆下走不通**：main 那一步会因 “refusing to merge unrelated histories” 直接失败。

而 custom 与上游合并基为 `01d7228b7e`（正确的旧上游 tip），可直接合并。故本次**直接 `custom merge upstream/main`**，main 保持不动（它已是 custom 的祖先，且此前 PR #19 已把 custom 合进 main，不再是「纯净分支」）。

## 二、合并冲突预判（8 个文件）

用 `git merge-tree --write-tree` 预演，冲突文件共 8 个，均可人工解决：

| `src/renderer/src/store/index.ts` | 上游新增 store 探针（`withStoreIdentityChurnProbe`）；custom 新增 Pi / ZCode usage slice | **两边都保留**（合并叠加） |
| `src/renderer/src/store/slices/usage-provider-slices.ts` | 同上（custom 的 Pi/ZCode provider） | 两边都保留 |
| `src/renderer/src/i18n/locales/en.json` | 语言包大改 | 以上游为基 + 保留 custom 独有键（日历 / ZCode / Pi） |
| `src/shared/global-settings-types.ts` | 上游新增设置项（terminalInlineImages 等）；custom 新增字段 | 两边都保留 |
| `src/main/runtime/rpc/methods/client-ui-schemas.ts` | schema 演进而冲突 | 以上游为基，保留 custom 追加字段 |
| `src/main/codex-accounts/runtime-home-settings-test-fixtures.ts` | 测试夹具 | 以上游为基 |

非冲突但高风险（自动合并成功，须人工复核）：

- `src/shared/tui-agent-config.ts` / `agent-catalog.tsx`：二开新增 agent（zcode / pi）的注册表，约 15 处注册点是历史踩坑区（新增 agent 必改注册表）。
- `config/electron-builder.config.cjs`：appId `com.penghuizhang.orca-s`、打包身份，不能丢。
- `.workbuddy/**`、`AGENTS.md`：二开文档与规则，上游不涉及，应零冲突。

## 三、执行步骤

1. 提交工作区遗留知识产物（记忆 / 设计文档），保证合并前工作区干净；
2. 建安全备份 tag：`backup/pre-sync-20260919`（合并失败可一键回退）；
3. `git merge refs/remotes/upstream/main`（在 custom 上），逐个解决上表冲突；
4. `pnpm install`（锁文件随上游演化）+ 类型检查；
5. `node config/scripts/verify-features.mjs`（二开功能完整性门禁）；
6. `node config/scripts/build-orca-s.mjs --install`（打包并装到 `/Applications`，脚本自动渲染验证 + ditto 安装 + 去隔离属性）；
7. 推 origin/custom；
8. 写日记忆 + 更新 MEMORY.md。

## 四、风险与回退

| 风险 | 缓解 |
|------|------|
| 合并冲突解错导致二开功能丢失 | merge 前打 tag；verify-features 门禁；打包前 typecheck + 人工复核 8 个文件 |
| 打包失败或产物启动崩溃（历史踩坑：React #185 类问题只在打包版复现） | 保留旧 `/Applications/orca-s.app` 安装包版本记录，必要时回退 tag 重新打包 |
| 上游依赖大改导致 `pnpm install` 失败 | 已配 `ELECTRON_MIRROR` / npmmirror 国内镜像；失败则回退 tag |
| main 分支持续落后上游 | 本文档记录；后续如需恢复标准三步流程，须先 `git fetch upstream --unshallow`（历史全量下载，带宽成本高），本次不做 |
