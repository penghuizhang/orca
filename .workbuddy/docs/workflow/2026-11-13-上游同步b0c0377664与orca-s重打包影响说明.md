## 3. 网络前提（本轮已解，勿重踩）

- `git fetch upstream` **静默失效**（浅克隆）+ 全局 `url.git@github.com:.insteadOf https://github.com/` **把 HTTPS 改回 SSH** ⇒ `http.proxy` 不生效，SSH 直连 ~25 KB/s 挂死（首次实测 10 分钟毫无进度）。
- 达标写法（**URL 带 `:443`** 才能绕开 insteadOf 前缀匹配）：

```bash
git -c credential.helper= -c http.proxy=http://127.0.0.1:54687 \
    fetch 'https://github.com:443/stablyai/orca.git' \
    '+refs/heads/main:refs/remotes/upstream/main' --force
```

实测 ~1.2 MB/s，本轮 incoming pack ≈ **491 MB** 拉完（上轮 22 MB；本轮增量大是因为上游重命名被当成全量对象传输）。
- 系统代理实测为 `127.0.0.1:54687`（`scutil --proxy` 复核）；clash-verge 的 50689 未转发，**不要用**。
- **不要拉 `refs/heads/*`**（上游近 8000 分支）。

## 7. 风险与前置约束

- **【约束】必须 primary worktree 操作**，子 agent 的绝对路径一律不跟。
- **【约束】不碰 `main`**；禁止往 main/master 提 PR。
- **【约束】打包只在 `custom` 上做**（`build-orca-s.mjs` 硬性拒绝非 custom 分支，无跳过开关）。
- **【约束】打包前**：`mobile/` 独立 workspace 必须 `pnpm install`；未跟踪文件必须清（`verify-features` 只豁免 `?? .codegraph/`）；无未合并本地分支。
- **【约束】合并提交必须 `--no-verify`**；`cmd | tail` 不能用来判成败（管道会把失败显示成 exit 0）。
- **【约束】不能在 agent 内重启 orca-s**（本会话进程链在 orca-s 终端里）⇒ 打包完成后交用户 Cmd+Q。
- **【风险】187→56 的冲突里最贵的不是「解」，是「上游删掉的模块里二开还在引用」**：`pnpm tc` 之后预计还会有 10+ 处集成缺口（上轮 11 处，其中 2 处运行期破损）。**tc 绿 ≠ 功能好**，二开四个功能（笔记 / 日历 / zcode·pi 用量 / 浏览器自动化）需单独跑测试 + 抽查。
- **【风险】并发会话**：若发现本 worktree 有别的会话在动索引/工作区，立刻停下不动索引、把成果先提交成分支（2026-10-17 踩过）。
