# 笔记编辑器加载修复方案

- 日期：2026-09-21
- 状态：待评审
- 关联：笔记功能设计方案 `.workbuddy/docs/notes/2026-09-21-笔记功能设计方案.md`

## 一、问题

笔记页面可以创建文件（落盘 `~/OrcaNotes/xxx.md`），但编辑器无法加载内容：

> 无法加载文件 — Connecting to the remote host... retrying once the workspace is ready.

根因：`NOTES_WORKTREE_ID = 'global-notes'` 是虚拟 worktree，但**没有像 `FLOATING_TERMINAL_WORKTREE_ID` 一样被标记为 local-only**，导致 EditorPanel 的文件加载链路走远程 host 连接。

## 二、根因分析

EditorPanel 文件加载流程：

```
openFile({ worktreeId: 'global-notes', runtimeEnvironmentId: null })
  → applyOpenFileToState → captureEditorFileOperationProvenance
    → resolveExplicitWorktreeOperationRouteResult → { kind: 'missing' }
    → throws OWNER_CHANGED_MESSAGE（toast：Couldn't verify which host owns this file）
  → useEditorPanelFileContentLoader
    → getConnectionIdForFile('global-notes', filePath) → undefined
    → isWorktreeConnectionResolved('global-notes') → false
    → throws WORKTREE_OWNER_NOT_READY_ERROR（Connecting to the remote host...）
```

**`FLOATING_TERMINAL_WORKTREE_ID` 为什么能工作**：在 3 个关键位置被 hard-code 为 local-only：

| # | 文件 | 作用 |
|---|---|---|
| 1 | `connection-owner-resolution.ts:60-62` | `getConnectionIdFromState` 对 floating id 返回 `null`（明确 local） |
| 2 | `editor-file-operation-owner.ts:50-57` | `captureEditorFileOperationProvenance` 返回 `{ executionHostId: 'local', runtimeEnvironmentId: null }` |
| 3 | `editor-file-operation-owner.ts:105-107` | `resolveCurrentEditorRoute` 同上 |

`NOTES_WORKTREE_ID` 不在这 3 处 → 走通用 worktree 解析 → 未知 repo → `undefined` → 抛异常。

## 三、修复方案

引入共享谓词 `isLocalOnlyVirtualWorktree(id)` 替代散落的 hard-code 比较。

### 3.1 新增谓词（`src/shared/constants.ts`）

```ts
/** Virtual workspace ids that are always local — never route through a remote host. */
export function isLocalOnlyVirtualWorktree(worktreeId: string | undefined | null): boolean {
  return worktreeId === FLOATING_TERMINAL_WORKTREE_ID || worktreeId === NOTES_WORKTREE_ID
}
```

放在 `constants.ts`，与两个常量同文件，shared 层可被 renderer 和 main 引用。

### 3.2 改动点（3 处，与 floating 既有 special-case 同位置）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `src/renderer/src/lib/connection-owner-resolution.ts:60-62` | 将 `=== FLOATING_TERMINAL_WORKTREE_ID` 改为 `isLocalOnlyVirtualWorktree(worktreeId)` |
| 2 | `src/renderer/src/lib/editor-file-operation-owner.ts:50-57` | 同上 |
| 3 | `src/renderer/src/lib/editor-file-operation-owner.ts:105-107` | 同上 |

每处只改条件判断，逻辑不变（返回 `null` / `{ executionHostId: 'local', runtimeEnvironmentId: null }`）。

### 3.3 不需要改动的部分

- `useEditorPanelFileContentLoader.ts` — 无需修改，上游 `getConnectionId` 返回 `null` 后自然走本地读取
- `runtime-file-read-client.ts` — 无需修改，`target.kind !== 'environment'` 时走 `window.api.fs.readFile`
- `NotesPage.tsx` — `openFile` 调用参数不变

## 四、约束清单

- 【约束】不修改 EditorPanel 核心加载逻辑，只在现有 special-case 位置扩展条件
- 【约束】`FLOATING_TERMINAL_WORKTREE_ID` 行为不变（回归保护）
- 【约束】新增谓词放 shared/constants.ts，不引入新模块
- 【约束】改动 ≤5 个文件，每处 ≤3 行
