# 笔记功能设计方案（语雀式本地笔记工具）

- 日期：2026-09-21
- 状态：待评审
- 关联：`src/renderer/src/components/editor/RichMarkdownEditor.tsx`（浮动工作区编辑器，直接复用）、`src/renderer/src/components/calendar/CalendarPage.tsx`（固定页实现范式）、`src/renderer/src/components/sidebar/SidebarNav.tsx`（导航项注册范式）

## 一、需求背景

用户日常用右下角「浮动工作区」写临时 Markdown 草稿，但浮动工作区是临时性质：文件在应用私有目录（`~/Library/Application Support/orca-s/floating-workspace/`）、平铺标签无目录树、无法承载结构化笔记。希望参照「日历」固定导航页的方式，新增一个类似语雀的「笔记」功能：左侧目录树可创建目录/文件，右侧编辑区能力与浮动工作区完全一致。

**已确认决策（2026-09-21）**：

1. **存储方式**：真实文件夹落盘，`.md` 是真实文件，支持用户选择根目录（Finder 里可直接看到、其他编辑器可打开）。
2. **浮动工作区**：共存不动，浮动面板继续负责快速草稿/终端/浏览器；笔记页是新增独立功能。
3. **入口**：「笔记」，图标 NotebookPen，位于侧边栏「日历」下方。

## 二、方案总览

新增 `TopLevelView 'notes'`（完整视图注册链路，照日历模式），侧边栏新增「笔记」按钮；新建 `NotesPage` 两栏布局（左侧目录树 + 右侧编辑器）；编辑器 **100% 复用 `RichMarkdownEditor`**（工具栏 H1-H5/粗斜删/列表/引用/链接/图片/表格/公式/斜杠命令/大纲/搜索全保留，与浮动工作区一致）；存储链路新增 `notes` IPC + preload bridge，全部为**真实文件系统操作**；笔记根目录默认为 `~/OrcaNotes`，首次进入可引导选择或页头随时切换。

### 核心数据流

```
点击目录树中的 .md 笔记
  → window.api.notes.read(path)                ← 主进程 fs 读文件
  → RichMarkdownEditor(content, onContentChange, onSave, showTableOfContents)
  → Ctrl+S / 防抖自动保存 → window.api.notes.write(path, content)

目录树 CRUD（新建文件夹 / 新建笔记 / 重命名 / 删除）
  → window.api.notes.* → 主进程 fs 真实操作（mkdir / writeFile / rename / unlink）
  → 全部路径经根目录白名单校验（防 ../ 越界）
```

### 8.1 实施中的方案优化（与 §4 差异）

1. **未新建整套 notes CRUD IPC**：实施时发现现有 `window.api.fs` bridge 已含全套文件操作（`readDir` / `createFile` / `createDir` / `rename` / `deletePath` / `writeFile`），且每条均经主进程 `resolveAuthorizedPath` 白名单校验。笔记页只需在打开时调 `notes:getRootDirectory` 完成一次**会话级目录授权**（`authorizeExternalPath`），此后全部 CRUD 复用 fs bridge——主进程新增代码从一个模块砍到一个 handler（`src/main/ipc/notes-directory.ts`，展开设置路径 → 首次 mkdir → 授权 → 返回）。
