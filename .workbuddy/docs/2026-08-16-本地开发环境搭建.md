## 实施步骤
1. 检查 Xcode Command Line Tools。
2. `nvm install 24`（若网络不可达则配置镜像）。
3. 用 Node 24 环境执行 `pnpm install`（首次 10-30 分钟：Electron 下载 + 原生模块编译；超时风险用后台执行 + 日志跟踪）。
4. `pnpm dev` 启动验证（后台运行，检查窗口/日志是否正常起来，确认无编译错误）。
5. 归档到 `.workbuddy/memory/2026-08-16.md`。

## 风险与对策
- **Electron 二进制下载慢/失败**：设置 `ELECTRON_MIRROR`（npmmirror）重试。
- **原生模块编译失败**：多为 Xcode CLT 缺失，先补齐；postinstall 为 rebuild-native-deps.mjs。
- **Node 版本错用**：install 与 dev 必须同一 shell 内保证 PATH 指向 nvm 的 v24。
- **验证方式**：dev 模式会持续占用终端 → 后台运行并检查日志关键字（electron-vite dev server 启动、无 fatal error）。

## 验收标准
- `node -v` → v24.x ✅（v24.19.0）
- `pnpm install` 退出码 0，无 error 日志 ✅（1m58s，postinstall 重建 node-pty 成功）
- `pnpm dev` 后台运行 30s+ 无崩溃，日志显示 electron-vite 已启动 ✅（Electron 窗口已打开，PID 1938 存活）

## 实施记录（实际结果）
- 步骤 1-2 顺利；步骤 3 踩坑：**nvm use 24 在非交互/后台 shell 中失败（exit 3）**，改用 `PATH="$HOME/.nvm/versions/node/v24.19.0/bin:$PATH"` 直接注入；前台交互 shell 中 `nvm use 24.19` 可用（完整带 v 前缀的也失败）。

- `pnpm dev` 启动正常：preload 构建 29ms、dev server :5173、Electron 打开。日志中 `MaxListenersExceededWarning` 与 `legacy worker provider-ready recovery failed (terminal_liveness_unavailable)` 均为无旧会话时的无害信息。
- dev 使用用户数据目录 `~/Library/Application Support/orca-dev`（与正式版隔离）。
