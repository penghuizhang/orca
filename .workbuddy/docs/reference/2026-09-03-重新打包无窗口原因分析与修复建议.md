# 2026-09-03 重新打包后无窗口：原因分析与修复建议

> 类型：故障分析（只分析、不改代码）。待用户确认修复方案后再实施。

## 一、用户报告的现象

- 按 mac 流程重新打包 orca-s，完成后双击/打开应用**没有窗口**。
- 用户体感"应该是有进程"，但界面确定没打开。

## 二、约束清单（动手前自查，来自历史记忆）

- 【约束】`configurePackagedUserDataPath()` 必须在 preflight 中被调用，否则 orca-s 与官方 Orca 共用 userData、单实例锁互斥（见 2026-09-02 记忆）。
- 【约束】本地包是 Apple Development 签名，`spctl` 显示 rejected 属预期，须右键打开/`open` 启动，双击 Gatekeeper 拦截与"无窗口"是两回事。
- 【约束】单实例锁失败时新进程以 exit code 3 静默退出（`SINGLE_INSTANCE_ALREADY_RUNNING_EXIT_CODE`），"打不开"可能是老进程仍在跑。
- 【约束】macOS 没有初始 reveal 兜底定时器（仅 win32/linux 有 10s fallback），renderer 首屏失败即永久隐藏窗口。

## 三、根因（按证据强度排序）

### 根因 A（主因，已实证）：打包流程根本没跑完，dist 仍是 9-2 旧包

- 复现：`node config/scripts/verify-features.mjs` 第 6 步"工作目录干净"报 ❌，
  原因是未跟踪目录 `.codegraph/`（`?? .codegraph/`）。
- `config/scripts/build-orca-s.mjs:80-88` 在 verify 失败时直接 `process.exit(1)`，
  后续 `build:desktop` / electron-builder 全都不会执行。
- 旁证：`dist/`、`dist/mac-arm64/orca-s.app`、` /Applications/orca-s.app` 时间戳均为
  9-2 17:01，与 HEAD（572a1f212f）一致；`git status` 干净（仅 `.codegraph/` 未跟踪）。
- 结论：用户"打包完"的包实际还是 9-2 的旧包，"打不开"并不是新包的问题。

### 现象 B（伴随，已实证）：旧实例仍在运行，新启动被单实例锁接管后退出

- `ps` 显示 9-2 构建的主进程仍存活（pid 42826，crashpad 标注版本与旧包一致），含 gpu/network helper。
- `open --stderr -a /Applications/orca-s.app` 返回
  `already running … redirected stdin/stdout/stderr could not be set`，
  即新进程走单实例锁把激活转给老进程后退出（exit 3）。
- 老进程窗口不可见（被关闭到托盘/隐藏/落在其他 Space），用户即看到"有进程、无窗口"。
- 说明：`focusExistingWindow → focusExistingMainWindow` 对隐藏窗口可恢复；
  Dock 单击在窗口实例存在但隐藏时由 `macos-app-activation.ts` 兜底不足，
  需从托盘图标/右键 Show 恢复，或彻底退出后重开。

### 风险 C（次因，历史痕迹）：renderer 曾出现 chunk 解析失败

- `~/Library/Application Support/orca-s/logs/main.trace.ndjson` 尾部（9-2 运行）有
  `lazy_chunk_reload` / `Invalid or unexpected token`。
- 按 `src/renderer/src/lib/lazy-with-retry.ts:149-171` 注释，这是 stale/truncated
  chunk 的典型 SyntaxError；macOS 无 reveal 兜底（见约束），若首屏 chunk 失败且
  恢复 reload 未落地，窗口 `show:false` 永久隐藏——这是 macOS 上"有进程无窗口"的放大器。
- 本次仅为历史痕迹，非直接证据；若重装新包后仍复现，优先查此链路
  （`ORCA_STARTUP_DIAGNOSTICS=1` 看 `open-main-window-start → window-created →
  ready-to-show/did-finish-load` 里程碑断在哪）。

## 四、已排除项（有证据）

1. userData 路径回归已排除：`main-process-preflight.ts:172-174` 仍调用
   `configurePackagedUserDataPath()`；`Application Support/orca-s` 目录正常，
   不存在与官方 Orca 共用锁的问题。
2. 日历 `customDbPath` 迁移不是本次原因：当前 userData 下无 `orca-custom.db`、
   无 customDbPath 配置；`store.ts:55（先 open 默认库）vs 66-68（后迁移拷贝）`
   的首启不一致只影响首启数据源，不会导致无窗口（记为已知小瑕疵，另行排期）。
3. ad-hoc 签名改动（3410ebbf30）只改 helper 签名参数，不影响窗口创建。
4. `spctl rejected` 为 Apple Development 签名预期行为，与无窗口无关。

## 五、修复建议（待用户确认后实施，不擅自改代码）

1. 【必做，最小修复】让标准打包链路恢复其一即可：
   - a) `.gitignore` 追加 `.codegraph/`；或
   - b) `verify-features.mjs` 第 6 步改为只检查已跟踪文件
     （`git status --porcelain --untracked-files=no`）/显式忽略 `.codegraph/`。
   推荐 b)，避免把 codegraph 索引行为与打包门禁耦合。
2. 【当前恢复】从托盘恢复或彻底退出老进程（注意先保存会话），
   修完门禁后重跑 `node config/scripts/build-orca-s.mjs --install` 再验证。
3. 【可选加固】给 macOS 补初始 reveal 兜底（对齐 win/linux 10s fallback），
   避免 renderer 首屏失败时永久隐藏；属上游行为变更，需单独设计评审。

## 七、实施记录（2026-09-03 09:00-09:40，用户确认修复后）

实际动手后发现两个更深的根因，§三的 A/B 只是表层：

### 根因 1（致命）：`CalendarPersistence` 构造器读了未赋值的 `runtime.state`

- 09-02 提交 c135f9e586（customDbPath）在构造器加了
  `runtime.state.settings`；但 `Store` 先 `createStoreDomains()` 后才赋值
  `runtime.state`（store.ts:55 vs 61），且 `state!`  definite-assignment 让 tsc 放行。
- 诊断启动实证：`[bootstrap] unhandled-rejection TypeError: Cannot read
  properties of undefined (reading 'settings')`，`store-loaded` 里程碑缺失，
  ready 链中止 → 主进程空转、无 renderer（ps 只有 network/gpu helper）。
- 修复：`runtime.state?.settings` + 回归单测
  `calendar-persistence.test.ts`（commit a598f1aabc）；全量 100+ 同类读取均在
  方法体内（构造后调用，安全），仅此一处在构造器。

### 根因 2（致命）：`build-orca-s.mjs` 用 `cpSync` 安装破坏签名 seal

- `cpSync` 把 framework 相对软链（`Versions/Current/*`）解析成指向 `dist/`
  的绝对路径 → `codesign --verify --deep --strict` 报
  `unsealed contents` → macOS 静默拒绝启动（exit 1、零输出）。
- 修复：改用 `ditto` 安装（commit ab0b4bbb68）。

### 附带：一次性的 asar 打包损坏

- 首个重打包含 `out/main/index.js` 条目起始错位 ~2KB（裸字节对照实锤，
  dist 与安装包一致坏）→ 主 bundle 解析失败 → 静默 exit 1。
- 仅重跑 electron-builder 打包即恢复（新包字节级验证健康），判为偶发；
  若再现再深挖 packer。

### 最终验证（新包 ab0b4bbb68）

- 里程碑：`store-loaded → services-initialized → open-main-window-start →
  window-created → did-finish-load → ready-to-show → window-shown` 全齐。
- Renderer 进程存活；verify 全绿；typecheck:node + 变更质量门禁全绿；
  日历单测 10/10 通过。

### 探查事故（自省）

- `open --stderr -a ...` 的 `--stderr` 会把 stderr 写进 CWD 名为 `-a` 的文件；
  `npx asar extract-file` 会在 CWD 落同名文件并曾截断覆写 `package.json`
  （已 `git checkout` 恢复）。教训：探查类命令一律远离仓库 CWD，
  用 `extract` 到 /tmp 或 python 读裸字节，事后必查 `git status`。
