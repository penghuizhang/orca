# 2026-08-16 任务入口置灰修复设计方案

## 背景与问题

新打包的 orca-s（custom 分支）全新安装、尚未添加任何工作区时，左侧导航栏「任务」菜单项置灰（`opacity-50 cursor-not-allowed`），点击无响应。截图（clipboard-2026-08-16-223126）确认：侧边栏「任务」灰色，其余菜单项（自动化/日历/Orca 手机端/搜索/Projects）正常，侧边栏底部显示「未找到工作区」。

## 根因

`src/renderer/src/components/sidebar/SidebarTaskNavButton.tsx`：

- `canBrowseTasks = repos.some((repo) => isGitRepoKind(repo))`（第 77 行）——工作区列表里没有任何 git 仓库时为 `false`。
- 主按钮 `onClick` 内 `if (!canBrowseTasks) return`（第 178 行）、`aria-disabled={!canBrowseTasks}`（第 185 行）、className 追加 `cursor-not-allowed opacity-50 hover:bg-transparent`（第 193 行）。

该置灰门禁是**上游设计**（`1a22e2d05` "UX/copy tweaks (#5142)"，2026-06-10），非本次打包引入的回归；`SidebarNav.test.tsx:473-491` 有专门测试固化该行为（无仓库时点击不触发 `openTaskPage`）。

「任务」页（TaskPage）本身已具备零仓库兜底：拉取链路有 `selectedRepos.length === 0` 守卫（gitlab 4964、github 6530/6679/7034），渲染有「No project sources selected」空态（`getRepoBackedTaskEmptyState`），零仓库下页面可正常渲染、不会崩溃。置灰纯粹是导航层的一刀切门禁，把用户挡在页面之外。

## 修复方案

### D1. 主按钮去置灰（核心）

`SidebarTaskNavButton.tsx`：
- `onClick` 不再拦截：无仓库时也调用 `openTaskPage()`。
- 移除 `aria-disabled={!canBrowseTasks}`。
- className 移除 `!canBrowseTasks && 'cursor-not-allowed opacity-50 hover:bg-transparent'`。
- **保留** `canBrowseTasks` 对 hover 快捷图标（GitHub/GitLab/Linear/Jira/Gitee）与 `handlePrefetch` 的门禁——无仓库时打开某个 provider 的专用页没有意义，且快捷图标本身已有 no-op 处理，行为不变。

### D2. 任务页零仓库空态引导

全新安装场景下，用户点击「任务」后会看到「No project sources selected / Select at least one project source…」——此时项目选择器里什么都没有，「选择项目源」对用户是空话。补充无工作区专属引导：

- `task-page-empty-state.ts`：`getRepoBackedTaskEmptyState` 增加 `hasNoWorkspace: boolean` 参数；当 `selectedRepoCount === 0 && hasNoWorkspace` 时返回新文案：
  - title：`No workspace yet`（还没有工作区）
  - description：`Add a workspace (a git repository) to start browsing tasks.`
- `TaskPage.tsx` 两处调用（github 3596 / gitlab 3661）传 `hasNoWorkspace: repos.length === 0`。
- GitHub（10378 附近）与 GitLab（10902 附近）空态块：当 `repos.length === 0` 时在描述下方渲染「Add workspace」按钮，点击 `openModal('add-repo')`——即侧边栏 FolderPlus「Add Project」的既有入口（零仓库下唯一可用入口；「+ New workspace」按钮在零仓库时是禁用的，`SidebarHeader.tsx:77`）。

### D3. i18n 新增键（`auto.components.taskPageEmptyState` 命名空间）

- `noWorkspaceTitle` = "No workspace yet"
- `noWorkspaceDescription` = "Add a workspace (a git repository) to start browsing tasks."
- `addWorkspace` = "Add workspace"

en.json 由 `pnpm sync:localization-catalog --fix` 自动补齐；zh/es/ja/ko 手工补键（惯例：缺键回退英文）。

### D4. 测试更新

- `SidebarNav.test.tsx`：「keeps unavailable Tasks context-menu-capable while left click remains inert」重写为「无仓库时 Tasks 仍可点击打开任务页」——folder repo 场景下点击应调用 `openTaskPage`，快捷图标仍不渲染。
- `task-page-empty-state.test.ts`：新增 `hasNoWorkspace` 用例。
- 若 TaskPage 测试中有断言空态文案的用例，同步核对。

## 影响面与风险

- 改动仅 renderer 导航层 + 任务页空态，不涉 IPC/主进程/数据层。
- 上游后续同步：`canBrowseTasks` 门禁是上游代码，本次为 custom 分支覆盖行为；上游每日 66 commits 合入时若该文件冲突，冲突面小（单文件、局部行）。
- 置灰行为本身是上游产品决策（无仓库时不给入口），本次按用户需求放开主入口；快捷图标门禁保留，行为收敛可控。
- 无仓库 + 点击任务：页面渲染既有空态（有 `repos.length === 0` 守卫的 fetch 路径不会发起任何请求），新增「Add workspace」按钮引导添加仓库。

## 验收

1. 全新环境（无工作区）：侧边栏「任务」正常黑色可点击；点击后进入任务页，显示「还没有工作区」+「Add workspace」按钮；点按钮弹出 add-repo 弹窗。
2. 添加 git 仓库后：「任务」可正常浏览任务，快捷图标（hover）出现且可点。
3. 仅 folder 工作区：任务页显示原「No project sources selected」文案（不误显示「还没有工作区」）。
4. 单测：`SidebarNav.test.tsx`、`task-page-empty-state.test.ts` 全绿；`pnpm lint` 通过。
