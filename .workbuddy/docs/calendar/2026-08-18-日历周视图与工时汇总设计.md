# 日历本周概览与工时清单设计方案

- 日期：2026-08-18（V2，按用户反馈调整）
- 状态：待评审
- 关联：docs/2026-08-16-日历功能设计方案.md、docs/2026-08-16-日历优化-点击建条目与国际化.md、docs/2026-08-16-日历二期个性化功能设计.md

## 一、需求背景

用户用日历功能记录每天的工作，周五集中填报工时到公司系统。痛点是：月视图格子小（每格最多 3 条）、没有按周汇总工时的能力、缺少"一键把本周工作整理成清单"的通道。

**用户反馈（2026-08-18）**：保持现有月视图效果不变，不做周视图切换；喜欢「复制本周清单」交互——点击后弹出页面，可预览并可复制。

## 二、方案总览

在现有月视图三栏布局（左侧分类筛选+农历+月历缩略图、中间月网格、右侧当日详情）**完全不动**的前提下：

- 页面底部新增一条**本周概览条**：本周（周一～周日，含跨月）条目数、各分类小计、**工时合计**。
- 概览条右侧一个「复制本周清单」按钮：点击弹出**预览对话框**，展示按天分组的 Markdown 清单，含「复制到剪贴板」动作按钮。
- 工时由条目的 startTime/endTime 自动计算（纯前端），**不改数据库结构**；allDay 条目不计工时；0.5h 向下取精度；end==start 的占位点不计入合计。

### 周五操作流程

```
周五打开日历（月视图原貌）
  → 底部概览条确认：本周 13 条 · 合计 16.0 小时
  → 点「复制本周清单」→ 弹出预览对话框
  → 点「复制」→ 粘贴到公司工时系统，完成填报
```

## 四、实现要点

### 4.1 底部概览条（新组件 `calendar-week-summary.tsx`）
- 渲染位置：`CalendarPage.tsx` 三栏卡片底部（卡片内 `border-t` 分隔条），不占用网格空间。
- 数据：**本周（以当前选中日期所在周为准，周一为首日）**内的全部条目；分类筛选 visibleCategories 生效（筛选后合计/计数随之变化）。
- 展示：`本周概览` + 4 个分类彩色圆点计数 + 共 N 条 + 右侧 `合计 X 小时`。
- 周五**高亮提示**（可选拍板项，默认不做）：当选中周内包含周五且周五为今天时显示「今天可填报工时」小字。

### 4.2 工时计算（纯函数，新增 `calendar-time.ts` 的 `hourSpan` 系列）
- 非 allDay 且 startTime/endTime 齐全：`(end - start) / 36e5` 小时，向下取 0.5 精度（09:07–10:52 → 1.5h）。
- end==start（占位时间点）不计入合计。
- allDay 条目不计工时。
- 全部为展示层计算，不落库、不改 IPC、不改 schema。

### 4.3 复制清单对话框（新组件 `calendar-week-list-dialog.tsx`）
- 复用现有 `ui/dialog.tsx`，内容区为 `scrollbar-sleek` 可滚动 `<pre>`（Markdown 原样预览）。
- 「复制到剪贴板」：`navigator.clipboard.writeText`，成功 toast 提示；失败（权限/非安全上下文）降级为提示手动选中复制。
- 关闭按钮 + 遮罩点击关闭，行为与现有条目编辑对话框一致。

### 4.4 清单格式（Markdown）
```markdown
# 2026-08-17 ~ 2026-08-23 工作清单

## 周一 8/17
- 09:00-10:30 评审迁移文档改造方案 (1.5h) [会议]
- 14:00-14:30 洗车相关的 bug 处理 (0.5h) [功能点]
小计 2.0h

## 周二 8/18
...
**合计 16.0 小时（13 条）**
```
- 无时间段的条目输出 `- 标题 [分类]（未计时）`，不进入小计。
- 无 emoji / 特殊格式，粘贴到任何系统不乱码。

## 五、可选增强（拍板项，默认不做）

1. **per-条目手工覆盖工时**：新增 `hours REAL NULL` 字段（v2 migration `ALTER TABLE calendar_entries ADD COLUMN hours REAL`），有值时优先于时间段计算；新建/编辑对话框加工时数字输入。**收益**：半天/整天这种没有精确时段的条目也能量化；**成本**：动 schema + normalize 链 + 表单，约半天。
2. **周报导出**：将清单保存为 .md/.txt 文件（可排二期）。

## 六、实施步骤（评审通过后执行）

1. `calendar-time.ts` 新增 `weekRangeDates(anchorKey)`（周一为首日生成 7 个 dateKey）、`weekRangeTitle`、`hourSpan`、`summarizeWeek(entries, weekDates, visibleCategories)` 纯函数 + 单测（覆盖跨月周、allDay 剔除、0 时长、0.5 精度、分类筛选）。
2. 新组件 `calendar-week-summary.tsx`（概览条）与 `calendar-week-list-dialog.tsx`（预览+复制），接入 `CalendarPage.tsx`（底部挂载 + 状态串联）。
3. i18n：新增 `auto.components.calendar.weekSummary/copyWeekList/copied/hoursSum/…` 键；en.json 由 sync 自动补，zh/es/ja/ko 手工补（遵循既有惯例）。
4. 校验：node/web/cli 三个 typecheck、calendar 相关单测全绿、oxlint/oxfmt（两个新组件控制行数，不新增 max-lines disable）。
5. 打包验证：`pnpm dev` 冒烟 → 按需 `build-orca-s.mjs` 重打包。

## 七、约束清单（实施时逐条自查）

- 【约束】月视图三栏布局与交互保持原样，不引入周视图切换。
- 【约束】不改数据库 schema（可选增强1除外），工时纯计算不落库。
- 【约束】周一为周首；跨月周按周一起止取整 7 天。
- 【约束】工时 0.5h 向下取精度，end==start 与 allDay 不计入合计。
- 【约束】分类筛选 visibleCategories 在概览条与清单同步生效。
- 【约束】新增组件不超 max-lines 300，不做 disable。
- 【约束】i18n 键遵循 `auto.components.calendar.*`，五语言同步。
- 【约束】复用现有 UI 原语（Dialog/Button/ScrollArea），不新造颜色/尺寸（STYLEGUIDE 裁决顺序）。
