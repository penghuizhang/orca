# 清单格式简化与分类自定义设计方案

- 日期：2026-08-18（晚）
- 状态：已实施（用户确认后按本方案完成，含「周合计与概览条合计均删除」的拍板）
- 关联：docs/2026-08-18-日历周视图与工时汇总设计.md（PR #8 已合并）、docs/2026-08-16-日历数据迁移sqlite设计方案.md、docs/2026-08-16-日历功能设计方案.md

## 一、需求背景（用户原话梳理）

用户周五用「复制本周清单」填公司工时系统，反馈两件事：

1. **清单输出太啰嗦**：不需要显示时间区间（`09:00-10:00`）、工时（`1.0小时`）、分类标签（`[会议]`）、每日小计（`小计 3.0小时`）——只要简洁的任务描述，且按 **1 2 3 编号**排列。
2. **分类希望可自定义**：现在是固定 4 类（会议/功能点/里程碑/其他），不能新增类型。

## 二、方案总览

- **需求一（清单格式简化）**：改动 `calendar-week-list.ts` 的 `buildWeekListMarkdown` 纯函数 + i18n 键，输出改为"编号+标题"的极简格式。**小改动**。
- **需求二（自定义分类）**：分类从"代码常量 + DB CHECK 约束"升级为"内置 4 类 + 用户自定义类"，新增 `calendar_categories` 存储表、CRUD IPC、侧栏管理入口。**中大型改动**（动 schema + shared 类型 + 全链路渲染）。

两条需求独立，可分别评审；需求二实施成本显著高于需求一。

## 三、需求一：清单格式简化

### 3.1 现状（PR #8 已合入的输出）

```markdown
# 2026年8月17日 – 8月23日 工作清单

## 周一 8/17
- 09:00-10:30 评审迁移文档改造方案 1.5h [会议]
- 14:00-14:30 洗车相关的 bug 处理 0.5h [功能点]
小计 2.0h

**合计 16.0 小时（13 条）**
```

### 3.2 目标输出（用户期望）

```markdown
# 2026年8月17日 – 8月23日 工作清单

## 周一 8/17
1. 评审迁移文档改造方案
2. 洗车相关的 bug 处理
```

### 3.3 格式规则

| 项 | 现状 | 目标 | 说明 |
|----|------|------|------|
| 标题 `# …工作清单` | 保留 | 保留 | 不动 |
| 日期标题 `## 周一 8/17` | 保留 | 保留 | 不动，`weekday long` 各语言自适应 |
| 条目前缀 | `- 09:00-10:30 标题 1.5h [会议]` | `1. 标题` | **每日重编号**；去掉时间区间、工时、分类标签 |
| 未计时条目 | `- 标题 [分类] (未计时)` | `n. 标题` | 同样只留编号+标题 |
| 每日小计 | `小计 2.0h` | 删除 | 不需要 |
| 周合计 | `**合计 16.0h (13 条)**` | 删除 | 用户确认「合计 XX 小时也不需要」（清单与底部概览条上的合计一并去掉；每小时展示由条目时间隐含，概览条仅保留各分类计数 + 共 N 条） |

- 空日整组跳过（现状已如此）。
- 任务标题为空时用「未命名」占位（现状已如此，键 `untitled`）。
- 排序沿用现状：分类筛选生效、allDay 优先、按开始时间。

## 四、需求二：分类自定义

### 4.1 现状事实（已核实代码）

- `shared/calendar-types.ts`：`CALENDAR_CATEGORIES = ['meeting','feature','milestone','other']` 联合类型；`isCalendarCategory()` 白名单校验，`normalizeCalendarEntry` 对未知分类回退 `'other'`。
- `main/custom-db/calendar-table.ts`：`category TEXT NOT NULL DEFAULT 'other' CHECK(category IN (...))`，v1 migration（`user_version=1`）已应用。
- `renderer/calendar-category-display.ts`：`DOT_CLASSES`/`LABEL_FALLBACKS` 均为 `Record<CalendarCategory, string>` 全量索引；各组件用 `CALENDAR_CATEGORIES.map` 遍历渲染。
- IPC：preload `calendar-api.ts` 4 方法，store `loading-store.ts` 透传 4 方法。**无分类管理接口**。
- 渲染链路：side-panel 筛选项、entry-dialog 分类下拉、month-grid/day-panel 圆点+标签、week-summary 分类计数、week-list 清单（需求一将去掉分类标签）。

### 4.2 目标模型

分类 = 内置 4 类（代码常量保留）+ 用户自定义类（持久化到 orca-custom.db 新表）。

```ts
// shared/calendar-types.ts
export const CALENDAR_CATEGORIES = ['meeting', 'feature', 'milestone', 'other'] as const
export type CalendarCategory = string  // 泛化：任何非空字符串都是合法分类标识

/** 分类展示元数据（内置类名走 i18n，自定义类名直接存） */
export type CalendarCategoryInfo = {
  id: string          // 'meeting' | 用户定义的唯一标识（如 'review'）
  name: string        // 显示名；内置类此处为 fallback 英文名（i18n 键优先）
  color: string       // tailwind 圆点色类：'bg-amber-500' 等
  builtIn: boolean    // 是否为内置类（内置不可删除/改名）
}
```

- `isCalendarCategory` 语义放宽：`typeof value === 'string' && value.length > 0`（非空字符串即合法）；`normalize` 对**空/非字符串**才回退 `'other'`，未知自定义 id 不再被抹掉。
- 自定义分类 id：由用户输入名称生成（英文/拼音/中文均可，唯一性校验；中文 id 需 URL-safe 处理，用 `encodeURIComponent` 或直接存原文——**选用直接存原文**，本机单用户场景无需安全字符约束）。

### 4.3 存储（orca-custom.db，v2 migration）

```sql
-- v2：分类表（seed 内置 4 类的显示名与颜色，作为归一化展示后备）
CREATE TABLE IF NOT EXISTS calendar_categories (
  id        TEXT PRIMARY KEY,              -- 'meeting' | 自定义 id
  name      TEXT NOT NULL,                 -- 显示名（内置=en fallback，自定义=用户输入）
  color     TEXT NOT NULL DEFAULT 'bg-zinc-500',  -- tailwind 颜色类
  built_in  INTEGER NOT NULL DEFAULT 0,    -- 1=内置不可删改
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
INSERT OR IGNORE INTO calendar_categories (id, name, color, built_in, sort_order, created_at, updated_at)
VALUES ('meeting','Meeting','bg-amber-500',1,0,...), ('feature','Feature','bg-blue-500',1,1,...),
       ('milestone','Milestone','bg-green-500',1,2,...), ('other','Other','bg-zinc-500',1,3,...);

-- v2b：移除 calendar_entries.category 的 CHECK 约束（SQLite 不支持 DROP CHECK）
-- 重建表：CREATE TABLE calendar_entries_new(... category TEXT NOT NULL DEFAULT 'other' ...) → 拷数据 → drop 旧表 → rename
-- 同一事务内完成，user_version 推到 2
```

⚠️ **CHECK 约束问题**：SQLite 无法直接删 CHECK，必须"建新表→拷贝→删旧→改名"。当前 v1 表已存在（用户机器上或c库已跑过），这是必须的迁移路径。新建表拷数据保留 id 主键、索引 `idx_calendar_entries_date` 一并重建。

> 已核实：`custom-db.ts` 的 `migrate()` 按 `user_version` 顺序跑 migration，每个 migration 独立事务、失败回滚——v2 天然支持这个重建流程。store 构造模板数组 `[CALENDAR_ENTRIES_TABLE_MIGRATION, CALENDAR_CATEGORIES_TABLE_MIGRATION]` 追加即可。

### 4.4 后端 CRUD（新增 IPC + store + 表操作类）

- 新文件 `main/custom-db/calendar-categories-table.ts`：`CalendarCategoriesTable` 类（list/create/update/delete）。
- 新 IPC 4 个：`calendar:categories:list` / `create` / `update` / `delete`（对齐既有 `calendar:*` 风格，preload `api-types.ts` + `index.ts` + `api/calendar-api.ts` 同步扩展）。
- store 委托 4 方法（对齐现有 calendar 5 方法写法）。
- **语义约束**：
  - `create`：id 由 renderer 端命名（或 main 端对重名抛错）；名称 trim 后非空；颜色必填、取值限 tailwind 色板集合。
  - `update`：只允许改自定义类的 name；内置类（built_in=1）抛错拒绝。
  - `delete`：**先查引用**——若 `calendar_entries` 仍有该分类条目则抛错拒绝，提示用户先改掉条目分类；无引用才删。
  - 颜色色板：固化一组 tailwind 字面量（`bg-red-500, bg-orange-500, bg-purple-500, bg-teal-500, bg-pink-500, bg-indigo-500, bg-yellow-500, bg-lime-500`）供自定义类选择；`DOT_CLASSES` 仅内置 4 类走 Record，自定义类按色板取。
  - `sort_order`：自定义类追加在末尾；侧栏/下拉按 `sort_order` 排序展示。

### 4.5 前端展示适配（关键：拆掉 Record 全量索引）

分类展示从「遍历 `CALENDAR_CATEGORIES` + 索引 Record」改为「遍历聚合列表 `allCategories = builtIn + customs`」：

| 位置 | 改动 |
|------|------|
| `calendar-category-display.ts` | 新增 `categoryColor(id, customMap)` / `categoryName(id, locale)` 解析函数：id ∈ 内置 → 原 DOT/LABEL + i18n 键优先；id ∈ 自定义 → 从表记录取 name/color；未知 → 灰点 + 原样 id。**去掉对未知键的 `undefined` 恐慌**（`DOT_CLASSES[id]` 未命中会渲染无颜色圆点） |
| `CalendarPage.tsx` | 新增加载 `calendar.categories.list()` 到 state；`visibleCategories` 类型改 `ReadonlySet<string>`；toggle 的全选判断从 `CALENDAR_CATEGORIES.length` 改 `allCategories.length` |
| `calendar-side-panel.tsx` | 分类筛选列表改为遍历 allCategories；底部加「+ 新增分类」入口 → 打开分类管理对话框（新增/改名/删类，内置类显示"内置"徽标不可删） |
| `calendar-entry-dialog.tsx` | 分类下拉遍历 allCategories；`FormState.category` 类型改 string（`buildInitialForm` 默认仍 'meeting'） |
| `calendar-month-grid.tsx` / `calendar-day-panel.tsx` | 圆点与标签改用解析函数（grid 只需圆点，day-panel 有标签文本） |
| `calendar-week-summary.tsx` | 计数 Map 的 key 遍历 allCategories（不再假设恰好 4 类） |
| `calendar-week-list.ts` | 需求一后已无分类标签；`categories` 字符串映射随 `WeekListStrings` 一起删除 |

### 4.6 新增分类管理对话框

- 新组件 `calendar-category-manager-dialog.tsx`：复用 `ui/dialog.tsx` + `ui/input.tsx` + 色板单选格（`size-3 rounded-full` 色块按钮）。
- 交互：① 新增行（名称输入 + 色板选择 + 保存）② 自定义分类行内改名/删除 ③ 内置类只读 + "内置"徽标。
- 打开入口：侧栏分类标题栏「管理」小按钮或列表底部「+ 新增分类」。

## 七、约束清单（实施自查）

- 【约束】SQL 变更必须归档到 `docs/06-SQL脚本/YYYY-MM-DD-*.sql`，禁止直改不留脚本。

- 【约束】常用目录不被 gitignore（新增文件按工程惯例入 src/）。
