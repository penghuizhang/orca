# 日历数据库外部存储方案

## 背景

用户反馈日历数据不显示，排查发现：

1. **根因**：orca-s 应用的 `configurePackagedUserDataPath()` 函数已定义但从未被调用，导致 orca-s 使用了官方 Orca 的 userData 路径（`~/Library/Application Support/orca`），而不是自己的路径（`~/Library/Application Support/orca-s`）
2. **数据状态**：日历数据实际存在于 `orca-s` 数据库中（29条记录），但官方 Orca 数据库为空
3. **用户需求**：希望将数据库文件放到外部目录（`/Users/zhangpenghui/software/sqlite`），避免版本更新时丢失数据

## 问题分析

### 当前数据存储位置

```
~/Library/Application Support/
├── orca/                          # 官方 Orca
│   └── profiles/local-default/
│       ├── orca-custom.db         # 日历数据库（当前为空）
│       └── orca-data.json         # 配置文件
└── orca-s/                        # orca-s 应用
    └── profiles/local-default/
        ├── orca-custom.db         # 日历数据库（29条记录）
        └── orca-data.json         # 配置文件
```

### 数据丢失风险

1. **应用卸载**：卸载 Orca/orca-s 时可能删除 userData 目录
2. **版本更新**：应用更新时可能重置 userData 目录
3. **手动清理**：用户手动清理 Application Support 目录时可能误删
4. **系统迁移**：系统迁移或重装时可能丢失

## 设计方案

### 方案 A：外部数据库路径配置（推荐）

**核心思路**：将数据库文件存储在用户指定的外部目录，应用启动时读取该目录的数据库。

#### 1. 配置外部数据库路径

在应用设置中添加数据库路径配置项：

```typescript
// shared/global-settings-types.ts
export type GlobalSettings = {
  // ... 其他设置
  /** 自定义业务数据库路径（为空则使用默认 userData 路径） */
  customDbPath?: string
}
```

      dbPath = customDbPath

#### 4. 添加数据库迁移功能

在应用启动时检查并迁移数据库：

```typescript
// src/main/startup/main-process-ready.ts
export async function initializeMainProcessReady() {
  // ... 原有逻辑

  // 检查并迁移日历数据库
  await migrateCalendarDatabaseIfNeeded()
}

async function migrateCalendarDatabaseIfNeeded() {
  const settings = getSettings()
  const targetPath = settings.customDbPath

  if (!targetPath) return

  const defaultPath = join(getUserDataPath(), 'profiles/local-default/orca-custom.db')

  // 如果目标路径不存在但默认路径存在，执行迁移
  if (!existsSync(targetPath) && existsSync(defaultPath)) {
    await copyFile(defaultPath, targetPath)
    console.log(`[calendar] Migrated database to ${targetPath}`)
  }
}
```

### 方案 B：数据库自动备份（补充方案）

在方案 A 的基础上，添加自动备份机制：

#### 1. 定期备份

```typescript
// src/main/persistence/loading-store/calendar-persistence.ts
export class CalendarPersistence {
  private backupTimer: NodeJS.Timeout | null = null

  startAutoBackup(intervalMs: number = 24 * 60 * 60 * 1000) {
    this.backupTimer = setInterval(() => {
      this.performBackup()
    }, intervalMs)
  }

  private async performBackup() {
    const backupDir = join(getUserDataPath(), 'backups')
    mkdirSync(backupDir, { recursive: true })

    const timestamp = new Date().toISOString().replace(/[:.]/g, '-')
    const backupPath = join(backupDir, `orca-custom-${timestamp}.db`)

    await this.calendarTable.db.backupTo(backupPath)

    // 清理超过 30 天的备份
    await this.cleanupOldBackups(backupDir, 30)
  }
}
```

#### 2. 导出/导入功能

在设置页面添加数据库导出/导入按钮：

```typescript
// renderer/src/components/settings/DatabaseSettings.tsx
export function DatabaseSettings() {
  const handleExport = async () => {
    const path = await window.api.showSaveDialog({
      defaultPath: `orca-calendar-backup-${Date.now()}.db`
    })
    if (path) {
      await window.api.calendar.exportDatabase(path)
    }
  }

  const handleImport = async () => {
    const path = await window.api.showOpenDialog({
      filters: [{ name: 'SQLite Database', extensions: ['db'] }]
    })
    if (path) {
      await window.api.calendar.importDatabase(path)
    }
  }

  return (
    <div>
      <h3>数据库管理</h3>
      <Button onClick={handleExport}>导出数据库</Button>
      <Button onClick={handleImport}>导入数据库</Button>
    </div>
  )
}
```

## 用户使用方式

### 配置外部数据库路径

1. 打开 Orca 应用
2. 进入 Settings → Advanced → Database
3. 点击 "Set Custom Database Path"
4. 选择目录：`/Users/zhangpenghui/software/sqlite`
5. 点击 "Apply" 并重启应用

### 数据备份

应用会自动在以下位置创建备份：

```
/Users/zhangpenghui/software/sqlite/
├── orca-custom.db                 # 主数据库
├── orca-custom.db-wal             # WAL 日志
├── orca-custom.db-shm             # 共享内存
└── backups/                       # 自动备份目录
    ├── orca-custom-2026-09-02.db
    └── orca-custom-2026-09-01.db
```

### 手动备份

1. 进入 Settings → Advanced → Database
2. 点击 "Export Database"
3. 选择保存位置
4. 数据库文件将被导出到指定位置

## 注意事项

1. **路径权限**：确保目标目录有读写权限
2. **备份完整性**：导出时确保数据库未被写入（应用关闭或使用 WAL checkpoint）
3. **版本兼容**：不同版本的数据库 schema 可能不兼容，导入时需检查版本
4. **数据一致性**：迁移过程中确保应用已关闭，避免数据损坏
