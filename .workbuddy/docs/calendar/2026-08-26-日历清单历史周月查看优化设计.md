# 日历「工作清单」历史周/月查看与复制优化设计

- 日期：2026-08-26
- 状态：已实施（2026-08-26，renderer 展示层泛化，零 schema/IPC/main 改动）
- 升级自：docs/2026-08-18-日历周视图与工时汇总设计.md（V2：月视图 + 本周概览条 + 复制本周清单）
- 关联：docs/2026-08-16-日历功能设计方案.md、docs/2026-08-16-日历二期个性化功能设计.md

## 一、问题背景

V2 上线后，"复制本周清单"只能复制**当前选中日期所在的那一周**（`weekRangeDates(selectedDateKey)`），且底部概览条只聚合"本周"。用户痛点：

1. **跨周看不到整体**：想看两周、或某段连续日期的工作，没有通道。
2. **历史不可查**：上周、上月、甚至去年某个月的工作记录，无法一键聚合查看或复制。
3. **缺整体视图**：底部只有"本周概览"，没有"选任意区间看汇总 + 复制"的能力。

**关键事实（代码现状）**：`CalendarPage` 通过 `window.api.calendar.list()` 一次性全量加载所有条目（`entries`），前端已有 `buildWeekListMarkdown` / `summarizeWeekHours` / `weekRangeDates` 等纯函数，且这些函数本质只依赖"一组有序 dateKey"。因此**把"周"推广为"任意区间"是纯展示层改造，零 schema / 零 IPC / 零 main 层改动**——本次只在 renderer 内做范围泛化 + 范围选择器。

## 二、方案总览

在月视图三栏与底部概览条**结构不变**的前提下，做两处升级：

- **底部概览条**：从"本周固定"升级为"区间可切换的概览"。左侧一个紧凑的**区间选择器**（本周 / 上周 / 本月 / 上月 / 自定义），右侧仍展示分类计数 + 合计工时；按钮改名「复制清单」，打开对话框时带入当前区间。
- **复制对话框**：升级为「工作清单」对话框。顶部带完整区间选择器 + ◀ ▶ 翻期（上周/上月/上自定义段），中部按天分组的 Markdown 预览覆盖所选区间，底部「复制到剪贴板」复制整段。

区间状态提升到 `CalendarPage` 共享：概览条与对话框用同一份 `WorkListRange`，对话框内改区间即时刷新预览。

### 交互流程

```
打开日历（月视图原貌，概览条默认"本周"）
  → 点概览条下拉切到「上月」→ 概览条立即显示上月 42 条 · 合计 80h
  → 点「复制清单」→ 对话框打开，默认区间=上月，预览上月全部工作
  → 点 ◀ 翻到「上上月」，或切「自定义区间」选 2026-03-01 ~ 2026-03-31
  → 点「复制」→ 粘贴到工时系统 / 存档
```

## 四、数据模型与范围抽象

### 4.1 新增区间类型（`calendar-time.ts`）

```ts
export type WorkListRange =
  | { kind: 'week'; anchor: string }            // 含 anchor 的周一~周日
  | { kind: 'month'; year: number; month: number } // 自然月 1 号~月底
  | { kind: 'custom'; start: string; end: string }  // 含端点的任意连续日

export function rangeDates(range: WorkListRange): string[]   // 展开为有序 dateKey[]
export function rangeLabel(range: WorkListRange, locale: string): string // 概览条/对话框标题
export function shiftRange(range: WorkListRange, dir: -1 | 1): WorkListRange // ◀ ▶ 翻期
```

- `week` → 复用现有 `weekRangeDates(anchor)`（周一为首）。
- `month` → 该年月 1 号至月底逐日。
- `custom` → `start`..`end` 逐日（含端点；start>end 时自动交换）。
- `shiftRange`：week 锚点 ±7 天；month `addMonths(±1)`；custom 两端同平移整段跨度。
- `rangeLabel`：week → `formatWeekRangeTitle`（如 "8月17日 – 8月23日, 2026"）；month → "2026年8月"；custom → "2026-03-01 – 2026-03-31"。

### 4.2 复用既有纯函数（零重写）

- `buildWeekListMarkdown(weekDates, …)` 仅依赖有序 dateKey 列表 → 入参改名为 `rangeDates`，重命名为 `buildWorkListMarkdown`，逻辑不变（按天分组、跳过空日、标题用首尾日期）。
- `summarizeWeekHours(entries, weekDates, …)` 同理直接复用，传入 `rangeDates(range)` 即得任意区间工时合计。
- 分类计数：概览条沿用现有 `collectWeekEntries(entries, rangeDates, …).reduce` 计数逻辑（重命名为 `collectRangeEntries` 仅改参名，或直接复用）。

### 4.3 预设区间计算（基于今天，不依赖月视图导航）

- 本周 = `{ kind:'week', anchor: todayDateKey() }`
- 上周 = `{ kind:'week', anchor: 今天-7天 }`
- 本月 = `{ kind:'month', year: 今年, month: 当月 }`
- 上月 = `{ kind:'month', year/month: addMonths(今年,当月,-1) }`
- 自定义 = 用户用两个原生日期输入选 `start`/`end`

默认区间 = 本周（与 V2 初始行为一致：默认选中今天，概览条即本周）。点月网格某天**不再**改变概览条区间（上报区间与选中日解耦，选中日仍用于右侧当日详情编辑）——这更贴合"选一段上报周期"的心智。

## 五、组件改动

### 5.1 新增 `calendar-range-picker.tsx`（范围选择器，两处复用）

- props：`value: WorkListRange`、`onChange: (r) => void`、`variant: 'bar' | 'dialog'`、`locale`。
- `bar` 变体：紧凑下拉（5 个预设），选中即 `onChange`。
- `dialog` 变体：预设下拉 + ◀ ▶ 翻期按钮（调 `shiftRange`）+ 选「自定义」时显示两个 `type="date"` 输入框（绑定 `start`/`end`，改即 `onChange` 自定义区间）。
- 复用现有 UI 原语（`Select`/`Button`/`Input`），不新造颜色/尺寸。

### 5.2 概览条 `calendar-week-summary.tsx` → 重写为 `calendar-range-summary.tsx`

- 接收 `range: WorkListRange`（替代 `weekDates`），内部 `rangeDates(range)` → `collectRangeEntries` 计数 + `summarizeWeekHours` 合计。
- 左侧 `rangeLabel(range)` 作标题；中部分类彩色圆点计数 + 共 N 条；右侧 `合计 X 小时` + 「复制清单」按钮（`onRequestCopy` 打开对话框，对话框继承 `range`）。
- 顶部插入 `<CalendarRangePicker variant="bar" … />`。

### 5.3 对话框 `calendar-week-list-dialog.tsx` → 重写为 `calendar-work-list-dialog.tsx`

- props 增加 `range` + `onRangeChange`；移除 `weekDates`。
- 顶部 `<CalendarRangePicker variant="dialog" … />`（含翻期 + 自定义输入）。
- 正文 `buildWorkListMarkdown(rangeDates(range), …)` 实时预览；标题随 `rangeLabel` 变化。
- 复制逻辑不变（`navigator.clipboard.writeText` + toast 降级）。

### 5.4 `calendar-week-list.ts` → 重命名为 `calendar-work-list.ts`

- `buildWeekListMarkdown` → `buildWorkListMarkdown`（首参 `rangeDates`）。`groupWeekEntriesByDay` 入参同步改名（内部仍用 `collectWeekEntries`）。

### 5.5 `CalendarPage.tsx`

- 新增状态 `const [range, setRange] = useState<WorkListRange>({ kind:'week', anchor: todayDateKey() })`。
- 移除 `weekDates` 记忆值（由 `range` 派生）。
- 概览条 / 对话框均接 `range` + `setRange`（对话框内改区间实时联动）。

## 六、清单格式（Markdown，沿用 V2 简化格式）

```
# 2026年7月 工作清单

1. 评审迁移文档改造方案
2. 季度规划会

## 周四 7/2
```

- 周区间标题沿用 `# {start} – {end} 工作清单`（不变）。
- 月/自定义区间标题用 `rangeLabel`（见 4.1）。
- 仍只输出 `1. 标题` 编号（V2 已简化：去时间/工时/分类标签/小计/合计），保持粘贴不乱码。

## 八、约束清单（实施时逐条自查）

- 【约束】月视图三栏布局、交互、农历/休班/连休横条全部保持原样，不引入周视图切换。
- 【约束】零 schema / 零 IPC / 零 main 层改动；纯 renderer 展示层范围泛化（`entries` 已全量加载）。
- 【约束】周一为周首；跨月周按周一起止取整 7 天；月区间取自然月 1 号~月底；自定义含端点。
- 【约束】工时计算规则不变：0.5h 向下取精度、end==start 与 allDay 不计入合计、分类筛选同步生效。
- 【约束】概览条与对话框共享同一 `WorkListRange` 状态，对话框内改区间即时刷新预览。
- 【约束】新增/重写组件单文件不超 max-lines 300，不新增 `max-lines` disable。
- 【约束】i18n 键遵循 `auto.components.calendar.*`，五语言同步；en.json 走 sync 自动补。
- 【约束】复用现有 UI 原语（Select/Button/Input/Dialog/ScrollArea），不新造颜色/尺寸（STYLEGUIDE 裁决顺序）。
- 【约束】跨平台：原生 `type="date"` 输入框在各平台均可达，无需额外键盘适配。
