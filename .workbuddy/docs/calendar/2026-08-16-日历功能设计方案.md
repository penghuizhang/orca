# 日历功能：设计方案与影响说明（待评审）

- 日期：2026-08-16
- 状态：**待用户评审**
- 分支：`calendar-feature`（建议自 `custom` 拉出；与 `gitee-integration` 平级，互不依赖）
- 需求来源：二开新增功能——侧边栏左上角（现有「任务自动化 Automations」旁）增加「日历」入口；日历用于排期/功能点/会议记录，条目可填写信息（如「今天有什么会」）

## 1. 背景与目标

用户要在 Orca 侧边栏增加一个**日历**功能页：日常排期、功能点、会议等信息填进日历条目，本地保存，随时查看。无云同步/无外部日历导入需求（一期）。

### 一期范围（本文档）

| 项 | 内容 |
|---|---|
| 入口 | 左侧栏新增「日历 Calendar」按钮（Automations 按钮旁边，默认显示） |
| 视图 | Apple 日历式布局：月视图网格（周一开头、日期+农历、今天红圈）+ 左侧分类筛选/迷你月历 + 右侧选中日条目面板 |
| 条目 | 新增/编辑/删除：标题、日期、全天/起止时间、分类（会议/功能点/里程碑/其他）、颜色、描述 |
| 交互 | 点选任意一天（含翻月/迷你月历导航到历史）查看该天条目；格内条目 chip 可直接点开编辑 |
| 存储 | 本地持久化，复用 `orca-data.json`（`src/main/persistence.ts`），纯本地无同步 |
| 导航 | 上月/下月/今天/新建；activeView 增 `'calendar'` |

### 二期候选（不在本次实施）

周/日/年视图切换器、搜索、跨天条目、重复规则（RRULE）、提醒通知、节气/节日徽标、条目关联 worktree/任务、导出 iCal、Google/Apple 日历同步、侧边栏隐藏开关（`showCalendarButton` 设置项）。

## 2. 现状调研（关键结论：Automations 就是现成范式，日历全程照抄接线面）

Orca 的「任务自动化（Automations）」是**同构功能**：独立页面 + 本地 CRUD + orca-data.json 持久化 + IPC + i18n。日历按同一模式新增即可，无新架构决策。

### 2.1 侧边栏入口（用户所说的「左上角」）

`src/renderer/src/components/sidebar/SidebarNav.tsx`：`showAutomationsButton` 时渲染 Automations 按钮（:128-156），点击 `openAutomationsPage()` → `activeView = 'automations'`。**日历按钮照抄此段**（lucide `Calendar` 图标，`translate('auto.components.sidebar.SidebarNav.*', 'Calendar')`）。

### 2.2 页面注册链路（automations → calendar 逐一对应）

| 层 | Automations 现状 | Calendar 要改 |
|---|---|---|

| 视图校验 | `shared/top-level-view.ts` `TOP_LEVEL_VIEW_LOOKUP`（Record 穷举，**漏加必 typecheck 报错**） | 加一行 |

### 2.3 数据与 IPC（本地 CRUD 范式）

- 持久化：`src/main/persistence.ts`，状态落 `userData/orca-data.json`；Automation 系列有 `normalize*` 归一化函数（:1022-1113）+ 默认值模式，旧数据缺字段安全。Store 类型方法形如 `listAutomations()` / `createAutomation(input)` / `updateAutomation(id, input)` / `deleteAutomation(id)`。
- IPC：`src/main/ipc/automations.ts` 定义 `ipcMain.handle('automations:list' | 'create' | 'update' | 'delete' | ...)`；在 `src/main/ipc/register-core-handlers.ts:46` 导入注册。
- preload：`src/preload/index.ts:4707` `window.api.automations.{list,create,...}`。
- 类型：`shared/automations-types.ts`（Automation / AutomationCreateInput / AutomationUpdateInput）。

### 2.4 其余 TopLevelView 枚举点（加 `'calendar'` 需逐一核对）

`'automations'` 出现在 renderer 14 处（无 test）：SidebarNav、AppWorkspaceShell、ui.ts、Settings.tsx、appearance-sidebar-search.ts、AppearanceWindowSidebarSection.tsx、automations-settings-search.ts、AutomationsPage、ExternalAutomationManagers、useSettingsNavigationMetadata、settings-navigation-types.ts、worktree-nav-view-history-replay.ts、titlebar-worktree-history-controls.ts、right-sidebar-visibility.ts、worktree-nav-history.ts。多数是 union 穷举（typecheck 强制），部分是 switch/映射需手动补。

## 3. 数据模型（一期）

```ts
// src/shared/calendar-types.ts
export const CALENDAR_CATEGORIES = ['meeting', 'feature', 'milestone', 'other'] as const
export type CalendarCategory = (typeof CALENDAR_CATEGORIES)[number]

// 预设色板（8 色，渲染用色点/条目底色；色值在实施时从 main.css token 语义色中取，不造新色）
export const CALENDAR_CATEGORY_COLORS: Record<CalendarCategory, string> = {
  meeting: '#f59e0b', // amber — 会议
  feature: '#3b82f6', // blue — 功能点
  milestone: '#22c55e', // green — 里程碑
  other: '#a1a1aa' // zinc — 其他
}

export interface CalendarEntry {
  id: string
  title: string
  /** YYYY-MM-DD，本地日期（月视图按此归格；不带时区偏移，单机本地应用避免换算混乱） */
  date: string
  /** 全天条目无起止时间 */
  allDay: boolean
  /** HH:mm，仅非全天 */
  startTime: string | null
  endTime: string | null
  category: CalendarCategory
  description: string
  createdAt: number
  updatedAt: number
}

export type CalendarEntryCreateInput = Omit<CalendarEntry, 'id' | 'createdAt' | 'updatedAt'>
export type CalendarEntryUpdateInput = Partial<CalendarEntryCreateInput>
```

存储：`persistence.ts` Store 增加 `calendarEntries: CalendarEntry[]`（默认 `[]`）+ `normalizeCalendarEntry` 归一化（非法日期/字段丢弃或回退默认），方法 `listCalendarEntries() / createCalendarEntry(input) / updateCalendarEntry(id, input) / deleteCalendarEntry(id)`。

## 4. 页面设计（参照用户提供的 Apple 日历截图，遵循 docs/STYLEGUIDE.md 与 main.css token）

用户参考图（macOS 日历）核心元素：左侧栏=日历分类勾选 + 底部迷你月历；主区=月视图网格（日期数字 + 农历、今天红圈、格内事件彩条）；顶部=「‹ 2026年8月 › + 今天」导航 + 「+」新建。用户明确诉求：**点选某一天可查看该天（含历史）条目**。

布局（对照 AutomationsPage 的自持 header 模式，页面内部再分左右两栏）：

```
┌────────────────────────────────────────────────────────────┐
│ 日历          ‹ 2026年8月 ›  [今天]              [+ 新建条目] │ header（pt-5，text-base font-semibold）
├──────────┬─────────────────────────────────┬───────────────┤
│ 我的分类   │  一  二  三  四  五  六  日        │ 8月16日 周日    │
│ ● 会议  ☑ │ ┌───┬───┬───┬───┬───┬───┬───┐    │ · 09:30 周会   │
│ ● 功能点 ☑│ │1初九│2初十│ …                  │    │ · 全天 功能点  │
│ ● 里程碑 ☑│ │[条目chip]                      │    │ · 14:00 评审  │
│ ● 其他  ☑ │ │      16⟨红圈今天⟩ 17  18       │    │               │
│          │ └───┴───┴───┴───┴───┴───┴───┘    │ [+ 新建条目]   │
│ ── 迷你月历│  （格子：日期数字+农历小字+条目chip） │  （选中日面板）  │
└──────────┴─────────────────────────────────┴───────────────┘
```

- **月网格**：自研纯 React，不引入第三方日历库（避免动 pnpm 锁文件）。**周一开头**；每格 = 日期数字（今天红圈描边、选中日底色高亮）+ **农历小字**（初一显示月名「七月」，其余初X/十X/廿X/卅X；用标准 1900–2100 农历数据表实现，实施时用 Python `lunardate` 生成对照向量单测验证）+ 当日条目 chip（分类色点 + 标题，`truncate`，≤3 条 + `+N more`，点击 chip 打开编辑）。
- **左侧内栏**（窄屏隐藏，`hidden lg:flex`）：分类勾选筛选（4 分类，色点 + checkbox，控制月网格/当日面板过滤显示）+ 底部迷你月历（紧凑 7×6，点击跳月/跳日，今天红点）。
- **右侧当日面板**（窄屏隐藏，`hidden md:flex`，~260px）：点选某天显示该天条目（时间/色点/标题/分类徽标，全天置顶，按时间排序），点击进入编辑；底部「+ 新建条目」（默认日期=选中日）。**看历史 = 迷你月历/翻月导航到过去月份点选任意一天**。
- **编辑对话框**：shadcn `Dialog`（用 `className`，无 contentClassName）；字段=标题（必填）、日期（默认选中日）、全天开关、起止时间（非全天）、分类（4 色）、描述 textarea。删除走确认。
- **配色**：跟随 Orca 主题 token（`bg-background`/`text-foreground`/border 系），不写死白底——参考图是浅色主题，Orca 深浅主题都要成立；今天红圈用现有红色语义 token（实施时从 main.css 取，不造新色值）；农历小字用 `text-muted-foreground`。
- 日期文本（月标题、星期、当日面板标题）用 `Intl.DateTimeFormat` 跟随应用 locale。

## 5. IPC 与接线清单

- `src/main/ipc/calendar.ts`：`registerCalendarHandlers(store)`，通道 `calendar:list` / `calendar:create` / `calendar:update` / `calendar:delete`。
- `src/main/ipc/register-core-handlers.ts`：导入注册（1 行）。
- `src/preload/index.ts`：`window.api.calendar = { list, create, update, delete }`（invoke 四通道）；`api-types.ts` 同步类型。
- 页面数据流：CalendarPage mount 时 `calendar:list` 拉全量（条目量小，一次拉取，不建缓存层）；CRUD 后乐观更新本地 state（create/update 用返回值覆盖、delete 过滤），失败 toast（sonner，照 AutomationsPage）。

## 7. 约束清单（实施时逐条自查）

1. 【约束-新增为主】新增文件为主（shared/calendar-types.ts、main/ipc/calendar.ts、renderer components/calendar/ 4 文件）；修改既有文件仅限接线（SidebarNav/ui.ts/AppWorkspaceShell/top-level-view/register-core-handlers/preload/persistence/枚举点）。persistence.ts 有 max-lines disable 豁免（文件头已有 eslint-disable max-lines），新增方法不改其行数约束。
2. 【约束-不引第三方依赖】日历组件自研，不新增 npm 依赖（上游 pnpm 锁文件严格，新增依赖增大 sync 冲突面）。
3. 【约束-视图穷举】`TopLevelView` 加 `'calendar'` 后，`TOP_LEVEL_VIEW_LOOKUP`（Record 穷举）必须同步加，否则 typecheck 报错；renderer 14 处枚举点逐一核对（typecheck 能抓 union 类，switch/映射类需 grep 自查 `'automations'` 出现处）。
4. 【约束-IPC 双端验证】preload ↔ main 两端 handler 改完必须 grep 构建产物（out/main/index.js）验证通道存在（吸取 Gitee listRepos 事故：Edit 失败重读重试、不能只信 typecheck）。
5. 【约束-样式规则】renderer 滚动容器必须带 `scrollbar-sleek`/`scrollbar-editor` 类（oxlint require-styled-vertical-scrollbar）；颜色只用 main.css 语义 token 与 STYLEGUIDE 色板，不造新色值；Dialog 用 `className`（无 contentClassName prop）。
6. 【约束-行数门禁】单文件 < 300 行；若改 `parent-pr-checks-rows.ts` 之类近上限文件先查 `wc -l` 余量；不写任何 max-lines disable。
7. 【约束-持久化兼容】`orca-data.json` 反序列化必须容忍旧数据缺 `calendarEntries` 字段（默认 `[]`）；normalize 丢弃非法条目不崩。
8. 【约束-测试】shared 层（类型/normalize/时间工具）单测必写；ui.ts 导航动作参照 `ui-page-navigation.test.ts` 补测；IPC 层至少冒烟测（或说明豁免理由）。
9. 【约束-i18n】en.json 由 `sync:localization-catalog` 补 key，`verify:localization-extraction` 必须过；UI 文案全走 `translate('auto.components.calendar.*', fallback)`。
10. 【约束-分支】自 `custom` 拉 `calendar-feature` 分支（gitee-integration 未合并上游 main，不叠在其上）；docs/ 被 gitignore，设计文档不入提交。

## 8. 影响面与风险

- **改动面**：新增 ~15 文件、修改 ~20 文件（多为 1-2 行接线）；不动 automations/gitee 现有功能。
- **风险**：枚举点遗漏（typecheck 兜底大部分）；IPC 双端不一致（约束 4 的 grep 验证兜底）；与上游日更 merge 冲突（集中在 ui.ts/top-level-view.ts 热文件——上游也在动 TopLevelView 的概率低，但 sync 时留意）。
- **不变量**：不改变现有行为（Automations/任务/设置等页面不动）；`activeView` 新增值对旧构建的持久化数据安全（`isTopLevelView` 校验 + sanitize 回退 terminal 已有机制）。
