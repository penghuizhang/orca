### 关键发现（会话 A 未记录的部分）

1. **GitHub SSH 直连被限速 ⇒ fetch 挂死**（根因，非网络不通）
   - `upstream` 是 SSH（`git@github.com:`），系统代理 `127.0.0.1:54687`（Clash Verge）的
     `ExceptionsList` 含 `192.168.0.0/16` ⇒ SSH **绕过代理**直连 ⇒ `index-pack` CPU 0.1%、
     10 秒收 0 KB。`.git` 里还堆了 8 个历史中断的 `tmp_pack_*`（已清理）。
   - 解法：`GIT_SSH_COMMAND='ssh -o ProxyCommand="nc -X 5 -x 127.0.0.1:54687 %h %p"'`
     ⇒ 25 秒抓完。HTTPS 走 `https_proxy` 更快（4.5s vs 18.4s）。
   - **不要全量抓 `refs/heads/*`**：上游有 **7982 个分支**，全量包 248,953 objects 直接卡死；
     定向 `refs/heads/main:refs/remotes/upstream/main` 只差 219 objects / 87 KB。
2. **真实差距**：custom 与上游合并基停在 `8846987c99`（09-25），**落后 3010 提交**。
   `sync/upstream-a87aa4ccdb` 分支只有 docs 提交，真正的上游合并从未落地。
3. **Electron 二进制要走镜像**：仓库 `.npmrc` 无配置，GitHub 下载卡死 9.5 分钟；
   `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 后 30 秒装好 43.7.8。
4. **`en-runtime-required.json` 是生成物**（`generate-runtime-required-english-catalog.mjs`），
   **不该手工解冲突**；用 `--fix` 重新生成产出 **2428** 条，与人工解冲突版**零差异**。
