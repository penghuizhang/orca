### 关键决策（含与原设计的差异）

1. **放弃自建 notes CRUD IPC，复用 fs bridge + 会话授权**
   设计文档原方案是新建 `notes:list-tree/read/write/...` 一组 IPC。实施读码发现 `window.api.fs` 已有全套文件操作（readDir/createFile/createDir/rename/deletePath/writeFile），且每条都过主进程 `resolveAuthorizedPath` 白名单校验；`authorizeExternalPath()` 授权某目录后其子孙全放行（会话级内存 Set）。⇒ 主进程只留 1 个 `notes:getRootDirectory`（读设置 → 展开 `~` → 首次 mkdir → 授权 → 返回），比原设计少一整个模块，且安全校验复用既有 containment 逻辑而非新写一份。
2. **编辑器复用 = openFile + EditorPanel（照浮动工作区同款机制）**
   浮动工作区 markdown 标签的真实实现：`openFile({ worktreeId: FLOATING_TERMINAL_WORKTREE_ID, suppressActiveRuntimeFallback: true })` 注册进 store `openFiles` → `<EditorPanel activeFileId />` 自取内容/保存/自动保存/脏状态/Cmd+S。笔记照抄，新增平行虚拟 id `NOTES_WORKTREE_ID = 'global-notes'`（shared/constants.ts），避免混入浮动工作区标签组。保存最终落地 `writeRuntimeFile` → 本地文件走 `fs:writeFile`，链路已验证。
3. **TopLevelView 注册点实际是 12 处，不是设计的 9 处**
   多出的三处都是读码踩到的：`worktree-nav-view-history-replay.ts`（前进/后退回放需加分支）、`ui-slice-task-actions.ts`（previousViewBeforeNotes 初始值）、`web/preload-api/web-app-api.ts`（web 端 API 适配层必须补 `getNotesRootDirectory`，typecheck 会抓出来）。**经验：新增视图时 grep `'calendar'` 全库跑一遍比对照清单更可靠。**
4. **i18n runtime-required 的判定规则**：`generate-runtime-required-english-catalog` 只收「plural 后缀 / 动态 fallback / fallback 与 en.json 不一致」的键；所有 translate() 字面 fallback 与 en.json 完全一致的键不需要进 runtime-required。所以 27 个 notes 键零补录，四验证全绿。
