## 答疑：Orca「本地服务器」是什么 + 云服务器接入路径（Q&A，未动代码）

用户问：Orca 的本地服务器是什么？有台云服务器，能否结合接入。

**结论**：Orca 的「服务器」= 每个 Orca 实例内置的 WebSocket RPC 服务（默认端口 6768，`src/main/runtime/runtime-rpc.ts`），手机 App / Web 客户端 / 远程 CLI 都通过它遥控整台 Orca（终端/worktree/任务/PR/浏览器/语音全部 RPC 从该实例拉取）。鉴权=设备令牌 + Curve25519 E2EE（应用层），配对=扫码 `orca://pair?code=`。

**两种接入云服务器的路径**（都无需改代码）：
- **路线 A（推荐，官方原生支持）**：云服务器本身跑 Orca headless —— `orca serve --port 6768 --pairing-address <公网IP/域名>`（Linux AppImage，无桌面自动起 Xvfb），systemd 常驻，`--pairing-address` 支持反代完整 URL（如 `https://域名/runtime`，nginx/caddy + wss 官方支持）；配对后手机/web 客户端随时连云端 Orca，7x24 在线可跑自动化。官方全文 `docs/reference/headless-linux-server.md`（含升级原子替换+回滚脚本、故障排查）。
- **路线 B（零代码中转）**：Orca 留本地，云服务器跑 frps + 本地 frpc 把 127.0.0.1:6768 隧道出去，Settings → Mobile 自定义地址填 `wss://域名:端口` → QR 通告该地址；与 2026-08-16 移动端调研的「路径 A 自建中转」同一件事。服务器只见加密流量。

**关键事实**：
- `serve` 子命令在本 fork 里存在（`src/cli/index.ts:27` 路由，`index-serve-command.test.ts`），定制版可直接打包 Linux 上云验证；
- 前提：Ubuntu 20.04+（glibc≥2.31）、公网 IP + 域名 + 证书（wss 必用，裸 ws 端口直开只建议内网/VPN）；
- 官方 Relay（relay.onorca.dev）也能跨网，但流量走官方云；自建路线数据才全部过自己平台。

**待用户拍板**：走 A（云端跑 Orca）还是 B（本地+隧道中转）；fork 定制版若要上云需先产 Linux AppImage。
