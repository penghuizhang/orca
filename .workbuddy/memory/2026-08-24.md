## 续三：完成通知「有提示音、无右侧弹窗、测试也不弹」根因诊断（纯诊断，无代码改动）

用户报：任务完成有通知提示音，但屏幕右上角无横幅弹窗；点 Settings→Notifications 的 Send Test Notification 也不弹。

### 代码实测定位（决定性证据）
- 声音与横幅是**两条独立链路**：
  - 横幅 = main 进程 `notifications.ts` `notifications:dispatch` → 经 `enabled`/`agentTaskComplete`/`suppressWhenFocused`/`cooldown`/`Notification.isSupported` 门禁 → macOS 下读 `readNotificationAuthorizationStatus()`，仅 `authorized` 才 `deliverNativeNotification()` → `new Notification(...).show()` 交给 macOS 渲染。
  - 声音 = renderer 端 `use-notification-dispatch.ts:232` 在 `result.delivered===true` 时调 `playDesktopNotificationSound()`（自定义声音走 `silent=true` + Orca 自己 `playSound`，不依赖 macOS 横幅）。
- **关键推论**：用户「能听到提示音」⇒ `result.delivered===true` ⇒ 已越过所有门禁、macOS 授权状态 = `authorized`（若 `denied`/`not-determined` 则 main 返回 `blocked-by-system`，连声音都不会响）。
- 授权=authorized 却无横幅 ⇒ 根因是 **macOS 通知「提醒样式」被设为 `None`**（授权通过但视觉不显示）。macOS 的 `UNUserNotificationCenter` 授权状态对 `style=None` 仍返回 `authorized`，故 Orca 自带 `MacNotificationPermissionCard` 会误报「delivered/已送达」，而系统实际什么都不弹。测试通知走同一路径（仅绕过 suppress/cooldown，仍受授权门禁）→ 同样不弹，完全吻合。
- 排除 `suppressWhenFocused`（默认 true）：若该门禁触发，main 返回 `suppressed-focus`、声音也不会响；用户有声⇒当时未聚焦该工作树或已关该开关，非主因。

### 结论
根因 = 运行中的 app bundle（orca-s / 官方 orca）在 macOS 系统设置→通知里的**提醒样式 = None**（或「允许通知」未开但更可能是 None，因为有声证明已 authorized）。orca-s 为 adhoc 自签，每次重打包后 bundle 身份刷新，通知样式极易被重置为 None，此坑复发率高。

### 修复（用户侧，无需改代码）
1. 系统设置 → 通知 → 找到正在运行的 app（orca-s 看 `com.penghuizhang.orca-s`，官方看 Orca）→ 确认「允许通知」开；
2. **提醒样式选「横幅」或「提醒」（勿选 None）**——这一步是横幅不弹的直接开关；
3. 关掉后再点一次 Send Test Notification 验证右上角是否弹；仍不弹则退出 app 重开让 bundle 重新注册通知。
4. 若面板出现 `MacNotificationPermissionCard` 显示「已送达」却无横幅，正是 style=None 误导，按上述改样式即可。
